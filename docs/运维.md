# NeoVNDB 运维

> 最后更新：2026-11-13
> 按情形查：出了什么状况、该看哪里、怎么办。命令与配置项的完整清单在根目录 `README.md`（Running、Commands、Scheduled jobs、Deploying）与各 `.env.sample`，这里不重复。

---

## 一、启动与停止

- `.\start.ps1` 起五个进程（读 API、图片镜像、用户服务、Next、边缘），等每个都能应答才算数，Ctrl+C 一起停；`.\stop.ps1`（或 `-Stop`）停掉上次留下的。只停自己记在 `.running.json` 里的进程。
- **改了代码要 `-Build`**（或只编后端 / 前端的 `-BuildBackend` / `-BuildFrontend`）：不带时用现有的 Go 二进制，前端跑 dev server。构建失败不会落到用旧产物启动。
- 端口被占默认拒绝启动；`-Force` 抢过来。
- 只从 `http://127.0.0.1:17030` 访问；Next 自己的端口（17034）只听本机，也不带 API 前缀。
- Postgres 不由脚本启动。

## 二、看日志

- 每个进程的输出在 `<名字>.out.log` / `.err.log`：默认在各自目录（`backend/vndb/api.*`、`img.*`，`backend/users/users.*`，`frontend/next.*`，`edge/caddy.*`），设了 `NEOVNDB_LOG_DIR` 就都在那里。
- 某个服务没起来时，`start.ps1` 会把它日志的末尾几行打出来。
- **HTTP 200 不代表页面能用**：健康检查只看状态码，查不出前端没水合。要确认前端真的活着，在浏览器里看（页面能交互、元素上有 `__reactFiber` 键）。

## 三、更新与导入

正常情况下什么都不用做：`serve` 进程每 24 小时检查一次上游，有新的就导入、过熔断、上线，并删掉更旧的归档。管理页 Mirror 组的 Update 卡能看到上次结果、下次时间与输出末尾，Check now 立即跑一次。

| 状况 | 原因与做法 |
|---|---|
| 更新报连不上上游或下载失败 | 1 小时后自动重试（`NEOVNDB_UPDATE_RETRY_AFTER`）。检查网络与代理：对外请求按 `HTTPS_PROXY` / `HTTP_PROXY`、再按 Windows 系统代理（Clash）走 |
| 报 "another run holds the lock" | 已有导入、上线或回滚在跑（定时、手动、管理页共用一把锁）。等它结束 |
| **熔断拒绝上线** | 新一代某表缩水超过阈值、少了表或派生表为空。先看输出里列出的异议：多半是归档被截断或导入中途停了，等下一期即可。确认是 vndb 真删了数据，可在管理页临时放宽熔断阈值，或 `neovndb db promote -force` |
| 上游比线上还旧 | `update` 拒绝倒退（那是镜像出问题的样子）。等上游恢复 |
| 状态页说 DDL 过期 | 线上一代由旧版建表语句建成；下次导入自动用新的。急的话手动 `neovndb update --force` |

## 四、回滚

- 管理页 Mirror 的 Roll back（二次确认）或 `neovndb db rollback`：把 `vndb_prev` 换回线上。
- 被回滚下来的那一代落到 `vndb_next`，所以再 `db promote` 就能前滚，不必重新导入。
- 响应缓存按代次做键，换代后旧缓存自然不再命中，不用清。

## 五、全年龄列表

- 每次导入自带。线上一代没有时（由更早的程序导入），遮罩"未就绪"，**谁都不遮罩**，`/meta/viewer` 报 `ready: false`。
- 补上不必重新导入：管理页 All ages 卡片的 Build the list，或 `neovndb db withheld`。用线上一代已有的数据建，约 3 秒，不用重启；读者在最后一步之前一直读旧表。
- 程序升级后规则变了（例如多了一张表），旧列表会被判为"未就绪"，同样再建一次。**注意要用新程序建**：正在跑的旧进程按旧规则建。
- 查数据库目录出错时，访客的请求回 503，不会因此被按不遮罩回答。

## 六、搜索用的派生物

- 搜索读每一代的 `search_labels` 视图（名字加上标签、特征的译名），描述检索读 `search_text` 表。新导入的一代都自带。
- 用旧版本导入的一代没有它们：`serve` 启动时当场补建视图；描述表在后台建（约 30 秒，持导入锁），期间描述检索回 503、说"还没准备好"，名字搜索不受影响。导入正在跑时就留给那次导入。
- 改了译名立即能搜到，不用重建什么。

## 七、图片

- 盘上没有的图默认 302 到 vndb 并在后台取回。读者连 vndb 不顺时，在管理页 Image settings 把"盘上没有的图"改成 fetch（服务器取回再给），不用重启。
- 预取每小时一轮、每轮 200 张；管理页 Images 卡显示覆盖率，Crawl now 立即跑一轮，`neovndb crawl --limit 0` 一次取完所有缺的。
- 预取连不上数据库时跳过这一轮，供图不受影响。

## 八、用户库备份与恢复

- 用户服务自己备份：最新一份超过一周就 `pg_dump` 一份到 `data/backups/users/`，留最新 8 份。管理页 Back up now 或 `users backup` 立即备份。
- 恢复：`pg_restore --clean --if-exists -d <数据库地址> <备份文件>`。
- 镜像库不备份：它随时可从上游重建（`neovndb update --force`）。译文语料在仓库里（`internal/trans/init.json`），管理页上改过的译文要导出（Export corpus 或 `neovndb trans export`）并提交，否则库丢了就丢了。

## 九、运行中可改的设置

- 管理页能改：更新间隔与重试间隔、留几份归档、熔断阈值、盘上没有的图怎么给、预取间隔 / 每轮张数 / 间隔、全年龄开关。改了立即生效。
- 存在 `data/settings/serve.json`、`images.json`，只存与 `.env` 不同的项，下次启动盖过 `.env`；改回 `.env` 的值就从文件里拿掉。CLI（`update`、`import`、`db check/promote`、`crawl`）读同一份文件。
- 文件里的值不合法时服务拒绝启动并报出文件路径；改正或删掉那个文件。

## 十、管理员

- 第一个管理员只能在本机授予：`backend/users` 下 `go run ./cmd/users admin <名字>`（`off` 收回）。之后在管理页 Accounts 里设。
- 管理页上不能对自己的账号设 / 撤管理员、强制登出或删除，免得把自己锁在门外。

## 十一、构建前端

- **站在运行时不要直接 `pnpm build`**：运行中的 `next start` 读 `frontend/.next`，构建会把它整个换掉，线上页面引用的脚本随即 500、交互全部失效。检查用的构建改用 `$env:NEOVNDB_NEXT_DIR = '.next-check'; pnpm build`；要换线上用的构建，就 `.\stop.ps1; .\start.ps1 -Build`。
- 已经弄坏了：重启前端（`.\stop.ps1; .\start.ps1 -Build`）。

## 十二、上线

步骤见 `README.md` 的 Deploying。要点：各 `.env` 从 `.env.sample` 起、保留样例里的上限；https 后面设 `NEOVNDB_USERS_SECURE_COOKIE=true`；`NEOVNDB_IMAGE_DIR` 写绝对路径；上线前跑一遍 `pnpm test:e2e:deployed`。

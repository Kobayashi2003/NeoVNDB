## 一、总览

Next.js 16.4（App Router）+ React 19 + Tailwind 4，TypeScript；关系图用 React Flow + ELK。约 10,800 行。

三条贯穿全局的约束，决定了目录为什么长这样：

- **列表状态全在 URL 里**。筛选、排序、翻页、标签页都是 query string，没有一个存在组件 state 里。因此任何一屏都可以直接粘贴链接复现，后退键行为天然正确，服务端渲染也不需要知道客户端有什么。
- **能在服务端渲染的就在服务端渲染**。详情页和列表页是 async server component，直接 `await` 取数；只有真正需要读浏览器状态的那一小块是 `"use client"`（原文开关、剧透等级、收藏按钮、图片灯箱……）。
- **偏好存在 cookie 里，服务端渲染时就知道**。`usePrefs` 仍是模块级 store（`useSyncExternalStore`，跨标签页共享），但"服务端快照"来自根布局从 cookie 读出、经 context 传下来的那份值——首屏与水合用的都是它。曾经它返回的是默认值，于是开着"原文"的读者每进一个页面都要看整页从英文改写成日文：实测 CLS 0.1676，全站最大。代价是三个原本静态的页面变成动态（偏好属于某个读者）。

### 取数路径

```
浏览器                                     服务端（Node）
  │ fetch("/vndbserve/vn?...")               │ fetch(NEOVNDB_API_BASE + "/vn?...")
  ▼                                          ▼
       Caddy :17030  ──►  backend/vndb :17031
       （两条路都过边缘，不存在"只在本地能用"的第二套地址）
```

前端只读两个环境变量，见 `frontend/.env.sample`：`NEOVNDB_API_BASE`（服务端取数走哪个边缘）与 `NEXT_PUBLIC_NO_IMAGES`（`start.ps1 -NoImages` 设置，构建时读入）。

`lib/api.ts` 是唯一出口，`lib/user.ts` 是用户服务的唯一出口。**页面要什么字段写在 `lib/fields.ts` / `lib/list.ts`**，不写在组件里——一个页面的代价因此是一处可读的清单，两个页面也不会对共用组件需要什么产生分歧。

### 测试

`pnpm test` 跑单元测试，`pnpm test:watch` 盯着跑，`pnpm typecheck:tests` 给测试做类型检查（根 `tsc` 不看 tests/）。`pnpm test:e2e` 跑端到端，要先 `start.ps1` 把站起来；单元测试文件叫 `*.test.ts`，端到端叫 `*.spec.ts`，两套运行器各认各的。**测试代码不进 `src/`**：`src/` 里没有任何文件引用 tests/，`next build` 也看不到它们。

`conditions.test.ts` 会读 `backend/vndb/internal/api/<type>/filters.go` 的筛选表，确认前端条件目录里的每个键后端都有——两边原本只靠注释"keep the two in step"。

组件测试与单元测试同一个 `pnpm test`：默认 node 环境，组件测试文件在文件头声明 jsdom。jsdom 不排版，所以凡是靠位置的（段落导航点亮哪段、横滚到没到头）由测试自己给元素设尺寸与位置；`offsetParent` 恒为 null、数字输入框回车不提交表单，这两处测试里各有说明。要量真实排版的（吸顶、对齐、溢出）放端到端。

**遮挡检查**（2026-10-17）：`layout.spec.ts` 另把页面与各滚动栏都滚到底，逐个检查正文里可点的链接与按钮，中心与四角任一点被 `position: fixed` 的东西压住即失败（Next 开发模式的徽标除外）；另有一条在收藏夹里打开选择，五种宽度下确认翻页链接不在操作条底下。最初只查中心点，漏掉了操作条压住翻页按钮下半截的情况（用户截图指出），改成五点后在去掉修复时能复现失败。

**排版检查自动化**（2026-10-16）：`layout.spec.ts` 在 320 / 390 / 768 / 1024 / 1440 五种宽度下打开二十几个主要页面（含登录后的收藏夹、评分、账号与管理页），整页与各个自己滚动的栏都不许横向溢出（有意横滚的行、日志框与关系图画布除外），出错时报出是哪个元素伸出了屏幕；再用 CDP 把网络限成慢 4G 量 CLS，超过 0.02 即失败，并列出移动的元素与前后位置。设 `E2E_SHOTS=<目录>` 会顺手存每页截图，供人工看。第一次跑就查出：段落导航等页面接管后才出现、把正文推下 54px（/v17 0.026）；折叠组件接管后才收起长简介、侧栏卡片上跳（/p24 0.021）；收藏夹、账号页的占位与正文复用同一个节点、被算成同一元素移动（0.11）；顶栏用户区的占位比用户名按钮窄、把搜索框挤动；管理页信息卡里的长路径在窄屏撑破页面。都已修，见第三节。

**按上线配置跑 e2e**（2026-10-16）：`pnpm test:e2e:deployed` 在现有站点旁另起一套：读 API 用 `.env.sample` 里的上限（开发的 `.env` 全是 0），Next 用生产构建，前面挂同一份 Caddyfile 起的边缘，用户服务是测试库上的临时服务（列表与页大小也用样例的值；登录注册次数仍不限，因为每条用例都从同一地址注册新账号，这两项另有后端测试）。它与现有站共用镜像库和图片，只读，不导入也不抓图。上限会不会在页面上撞墙，在这里先看到。第一次跑就撞到了：作品页请求 `characters.traits.translation.name`，嵌套 4 层，而样例的 `NEOVNDB_MAX_FIELD_DEPTH` 是 3——按样例上线，每个作品页都会是"That did not work"。样例与代码默认值改为 4，并加了 `tests/unit/ceilings.test.ts`：读样例里的这个数，检查每份字段清单，以后加字段越了界在单元测试就会失败，不用等到上线检查。

端到端里 `navigation.spec.ts`（2026-10-15）覆盖段落导航（宽屏与手机）、Similar 横滚、`/q` 只有一条结果时跳转、发行列表标题对齐、筛选菜单的分面计数、关系图只列有用的步数、关系图放大后卡片仍全部挂载且换步数时控制台无报错（不剔除视野外的卡片，去掉修复即失败）。

## 三、逐模块

### 3.1 `app/` —— 路由

| 文件 | 职责 |
|---|---|
| `icon.svg` | 网站图标（Next 按约定生成 `<link rel="icon">`） |
| `layout.tsx` | `<html>`、自托管字体（Righteous 做字标，配 metric-matched 回退字体以免换字时跳版）、Header |
| `page.tsx` | 首页：按月列出发行，月份在 URL 里 |
| `[slug]/page.tsx` | **一个动态段分发全部实体与全部列表**。vndb 的 id 本身就说明了类型（`v17` 是 VN），再加 `/v/` 前缀等于说两遍；`/v` 不带数字就是"全部 VN"。App Router 里静态段优先于动态段，所以将来加 `/about` 不受影响。`generateMetadata` 取标题时用的是页面自己的字段清单，与页面的请求一字不差，Next 把两者合成一次请求（2026-10-23 之前只取 `title`，每个详情页多问后端一次）；`rg/` 同理 |
| `[slug]/rg/page.tsx` | 关系图。画布占满顶栏以下的整屏，标题与步数选择放在左上浮动卡片里（与控制面板同一张卡）。步数在地址里（`?depth=`）；列出 1 到后端给的 `deepest`：不论问的是第几步，它都是"再深也画不出新东西"的那一步（图到头、`max_depth` 或节点上限，先到者为准），地址里的步数比它深时按它显示。2026-10-23 之前后端只说"后面还有"，前端只好至少列到 5，图三步就到头时也列 5 个（v84）。步数旁的 Deepest 一步跳到 `deepest`，已在最深处时变灰但不消失，免得那一行宽度变化。超过 8 个数字放不下卡片，改成"− N steps out +"的步进器 |
| `login/` `register/` `account/` | 账号三件套 |
| `u/page.tsx` | 收藏夹索引（改名、删除、新建） |
| `u/(shelf)/layout.tsx` | 单个收藏夹的布局：左边的列表栏属于布局，所以在列表之间切换时它不重画、不丢滚动位置 |
| `u/(shelf)/[id]/` | 单个收藏夹。不再按地址参数做 key：换页、换排序只换结果，标题与控件不动 |
| `u/ratings/` | 我的评分：独立页面（评分属于条目而不属于列表，所以旁边没有列表栏），按类型切换，批量设分或清除；入口在顶栏用户菜单的 Your ratings |
| `admin/page.tsx` | 管理页的壳，内容是客户端的 `AdminPanel`：服务端不知道是谁在看，三个服务的 `/admin` 路由只认管理员的 cookie（边缘把关）。未登录给 `SignInFirst`（见下），非管理员给"Administrators only"与授予命令。顶栏用户菜单里只有管理员才看得到 Administration |
| `api/page.tsx` | 读 API 的说明页，入口在列表页页脚（`DataAge` 的 "API" 链接）。内容取自后端的 `/meta/openapi`（由真正服务请求的字段表/筛选表/排序表生成），所以列出来的都能用；每个筛选的含义与取值写法从 `conditions.ts` 取，没进条件构建器的标 "text view only"。静态段，优先于 `[slug]` |

### 3.4 `components/ui/` —— 通用件

`ImageWithFallback` 挂载时会**主动检查 `<img>` 是否已经加载完**。缓存里的图、或者边缘直接从磁盘吐出来的图，常常在 React 水合之前就加载完了——那时 `onLoad` 还没挂上，load 事件落空，状态永远停在"加载中"，图片永远 `opacity-0`。状态同时带着它所属的 `src`，换图时从"加载中"重新开始，而不是继承上一张的"失败"（失败态不渲染 `<img>`，也就永远不会再试）。

`DetailShell` 的两栏与 `/u` 的两栏都是各自滚动的滚动盒：左侧各留 4px 内边距、再用等量负外边距抵消，定宽的一栏再补等量宽度；并且**始终保留滚动条槽位**（`scrollbar-gutter: stable`）——详见第四节。`/u` 的加载占位与加载完成后的面板共用同一组栏样式常量（`ROW` / `LISTS` / `BODY`），两者不可能对不齐。

`Name`（按偏好选脚本/译名）、`Description`（长文的同一件事）、`BBCode`（vndb 的 BBCode 方言渲染：裸 id 如 `v17` 自动成链；`[url=]` 只认 `http(s)://` 与站内 `/…`，其余只留文字；嵌套内容行内渲染，不会出现 span 里套 div；`[spoiler]` 里的标记同样渲染（2026-10-28 前原样显示，c3659 的 `[url]` 露了出来），未揭开时剧透是个按钮、里面不能放链接，所以按钮上画的那份链接只留文字，揭开后才是真链接；标签不分大小写，vndb 的描述里 `[URL=…]` 与 `[url=…]` 都有，裸 id 只认小写）、`SexLine`（性别一行，角色页与 VN 页的角色卡共用）、`InfoCard`/`Section`/`Segmented`/`TabBar`/`Tooltip`/`Collapsible`/`Lightbox`/`Spoiler` 等。

**段落导航**（`SectionNav`，2026-10-15）：`DetailShell` 在正文栏顶部放一行胶囊，列出这一页的各个 `Section`（名字与数量），当前在读的那段点亮，点击平滑滚过去。`Section` 自己带 `id`（标题转成 `voiced-characters` 这样，可以直接链接）、`data-section`、`data-count`，导航靠这些找段落，用 `MutationObserver` 跟着段落增减（角色展开视图会整个换掉正文）。在原位时就是一行和目录页标签一样的胶囊；滚动后吸顶（宽屏贴正文滚动盒的顶，手机贴顶栏下沿），这时才收进一张半透明浮卡，样式与关系图页的浮动面板一致，下面滚过的字不会透出来。不足三段不显示：这一条交给 `globals.css` 里的 `:has()` 规则判断，服务端的 HTML 里就已生效。慢网下浏览器会先画出解析到一半的页面，那时数段落总有一边会猜错：/v17 先藏后显、把正文推下去，/p24（段落少、作品列表长）先显后藏（生产构建下 CLS 都是 0.026，按上线配置的 e2e 发现）。所以 `DetailShell` 在主栏末尾放了 `#column-end` 标记，并用 `<link rel="expect" href="#column-end" blocking="render">`（React 会提到 head 里）让首帧等主栏解析完再画；不支持它的浏览器，在标记解析到之前导航一律保留位置。导航本身在服务端按完整高度画出、胶囊为空，接管后才填进去，所以正文不会被推下去（之前接管后才出现，慢网下 /v17 CLS 0.026）。最初试过贴在页面右缘的一列刻度（仿 Codex），挨着正文滚动条显得挤，用户看过后改成现在这样。跳转时段标题与浮卡之间的距离由 `Section` 的 `scroll-margin` 留出。

`SearchPill` 是三处"提交才搜索"的圆角搜索框（列表页、收藏夹页、顶栏）的共同外壳，差异（前面的标签、后面的清除链接）走 `before` / `after`。`Selection` 是一次选多条的两件东西：盖在卡片上的勾选框 `Selectable` 与贴在窗口底部的 `ActionBar`；收藏夹页的"移动/删除"条（`user/SelectBar`）和结果页的"存入"条（`results/Collecting`）都往里放自己的按钮。`ui/NewList` 是存入菜单底部的"新建列表"，收藏按钮、结果页存入条与保存搜索共用（文字由 props 换）。

`DetailControls`（七个详情页共用的一行控件：页面自带的 → 评分 → 收藏）在 `user/`，不在这里：它由评分与收藏两个用户功能组成，`ui/` 不依赖任何业务目录。

`Menu` 是全站弹出菜单的共用零件：`MenuPanel`（面板：按内容定宽，10–18rem；统一的边距、滚动上限与淡入）、`menuItem()`（行的样式，行本身仍是 `Link` 或 `button`——链接能在新标签页打开，按钮不能，这个区别不能被抹掉）、`MenuMark`（**多选是复选框，单选是单选圈**，读者点之前就知道点了是"加上"还是"换成"）、`MenuLabel`、`MenuDivider`。原先七个菜单各抄一份面板样式，宽度、边距、滚动上限各不相同。

淡入动画用 `translate` 而不用 `transform`：`useKeptOnScreen` 通过直接写 `transform` 把贴边的菜单推回屏幕内，动画若也动 `transform`，播放期间会覆盖它、播完再横跳一下。两个属性是叠加的。

`Trouble` 是"没东西可给、只有一个理由"的那种页面的共同形状：找不到和出错是同一个页面换套说法。

**内容分级、剧透起始等级与原文开关只在顶栏**（`ViewMenu`）。它们原先散在首页、列表页与四种详情页的侧栏里，收藏夹页反而够不到。注意 `DetailControls` 因此失去了首屏就占位的那个元素——评分与收藏都要等会话——所以那一行改用 `min-h-7` 自己撑住高度。

`ControlLabel` 值得单说：一排选项前面那个词（"Sort"）必须和选项本身长得不一样，否则会被当成选项之一——实际发生过。

**VN 页的数据**（2026-10-23）：VN 页要水合的数据原本占页面一大半（v11 生产构建 712 KB 的 HTML 里 457 KB 是 RSC 数据），其中 212 KB 是角色特征：31 个角色共 1,450 条，每条都带特征名、分组与译名。`VNPage` 改为服务端组件，交给客户端 `VNView` 之前先 `packTraits`：每个特征的名字、分组、译名只在 `book` 里出现一次，角色身上只留 `[id, 剧透等级, 是否谎言]`；同时先在服务端按本作筛掉声优。`VNView` 用 `unpackTraits` 还原，下游组件不变。v11 的 RSC 数据降到约 300 KB。再往下就是发行（70 KB）与标签（28 KB），都是页面真要显示的。整页改成服务端渲染收益很小：几乎每一段都随原文开关、剧透等级即时变化（`usePrefs`），放到服务端就要每次切换都回服务器。角色页、发行页只有几十 KB，不需要这样处理。

条件构建器在 `list/conditions/`，按职责分文件，依赖只朝一个方向（sentence → menus / editor → parts / context），没有环：

| 文件 | 职责 |
|---|---|

| `sentence.tsx` | 芯片句子：`Flow`（一组条件与连接词）、`Connector`、`SubGroup`、`Chip`、`Summary` |
| `menus.tsx` | 组的模式菜单、添加菜单、筛选列表（Properties / Related 两段）、类型图标 |

| `useCondition.ts` | 取条件定义；外链站点条件在这里换成按类型过滤的枚举（站点清单每页取一次） |
| `entity.tsx` | 弹出层里的按名搜索 `EntitySearch`，与芯片上显示名字的 `useEntityName`（页内共享缓存） |

树的编辑都走 `edit(key, fn, then)`，`then` 指定改完后打开哪个弹出层（`leaf<key>` / `add<key>` / `mode<key>`）；每次提交会**剪掉没填完的条件和空组**（正在编辑的除外），所以半截的条件不会进入 `f=`。

外链站点条件（`kind: "site"`）的选项来自 `/meta/extlinks`，每页取一次、所有芯片共用；芯片里 `useCondition` 把它换成按当前类型过滤的普通枚举，之后的编辑、多选、整理都不用另写。

取值的种类（`ConditionKind`）决定编辑器与可用比较：有序枚举（`ordered`，如动画程度）和分辨率（`resolution`，`1920x1080`）可以 ≥ / ≤，普通枚举只有是 / 不是；数字可带单位（`unit`，芯片上显示为"≥ 600 min"）；`credit` 是"某人 + 可选职位"（`s224:scenario`，`readCredit` / `writeCredit` 读写），编辑器先按名搜人、再选职位。

能装括号条件的由 `nestable` 判断（`relation` 与 `scored`，即标签/特征也能 `tag=(search=school)`）：编辑器给它们同一组四个模式（是这个 / 不是这个 / 有一个满足… / 没有一个满足…），芯片句子与"整理"都按它进到目标类型。

条件分两类：`conditions.ts` 的 `relatedType` 判断一个条件是否指向别的类型（`relation` / `entity` / `scored` / `credit`），构建器据此把添加菜单分成 Properties / Related 两段、给关联芯片加类型图标（`TYPE_ICON`）、让嵌套块换成天蓝色。

**不要用原生 `<select>`**：暗色页面里它弹出白底、看不见选项。选项一律用 `Menu` 的弹出层。

**页面宽度**：顶栏与所有页面共用 `max-w-page`（`globals.css` 里的自定义 utility：80rem，屏宽 ≥96rem 时 100rem），保证顶栏与内容对齐，改宽度只改一处。列表网格在 `2xl` 加到 7 列，卡片大小基本不变。

**翻页**：`Pagination` 画首尾与邻近几页，中间的"…"是 `PageJump`：点开变成页码输入框，回车跳转，超出范围的数夹到首页或末页（表单 `noValidate`，否则浏览器会因 `max` 拦下提交），Esc 或失焦收起。

**管理页**（2026-10-01）：`components/admin/`。Mirror 标签同时读三个服务的状态（各自失败各自显示），有任务在跑时每 2 秒跟一次、否则只读一次；按钮：Check now（立即更新）、Roll back…（二次确认）、Crawl now、Back up now。Translations 标签按 tag / trait 列出条目、默认只看缺译文的、可搜索；每个名字和描述各自保存（空串即删除），描述丢了标记服务端回 400 并显示原因；Export corpus 直接下载 init.json。Users 标签列出账号，自己那一行没有操作。时间按读者本地时钟显示到分钟，Go 的时长（`24h0m0s`）显示成 `1 day` 这样。

**过渡**（2026-10-03）：先实测了各种跳转（标记关键元素，逐帧采样），再按结果改：
- **服务端渲染的页面**（列表翻页、排序、筛选、目录页的标签页、首页换月、搜索）本来就只换内容，但从点击到新内容有 0.2–0.35 秒毫无反应。`components/layout/Navigation.tsx` 挂在根布局里：捕获阶段监听站内链接的点击（`next/link` 会 preventDefault，所以必须在它之前），程序化跳转走 `hooks/useNavigate.ts`，两者共用 `lib/navigating.ts` 的 store；因为在前面，它分不清哪些点击随后会被取消，所以会取消的链接要自己挂 `data-inert`（关系图选路径时点卡片、拖完画布松手在卡片上）；等过 120ms 还没到，顶上出一条细进度条，同时给 `<html>` 加 `data-navigating`，带 `data-results` 的结果区淡到一半（globals.css）。地址一变就结束，并把所有 `data-scroll-top` 的容器滚回顶部——宽屏下详情/目录页的内容栏、收藏夹的主栏是自己滚的，原先翻到第二页还停在页面中间（实测 626px）。
- **跳转时取消旧页没加载完的图片**（2026-10-18）：同一次点击里，`lib/navigating.ts` 把旧页上还没加载完的 `<img>` 的 `src` 属性拿掉。本地是 HTTP/1.1，同一地址只有 6 个连接；镜像还没取过的封面一张要几秒，占满后下一页的请求要排队（实测 15.1s，改后 0.15s）。拿掉属性而不是清空：清空会触发 `error`，`ImageWithFallback` 便把卡片标成坏图。跳转结束时，仍在页面上又没被 React 换掉 `src` 的图片还原（跳转没成，或新页保留了同一张卡片）。`lib/viewTransitions.ts` 还包了一层 `document.startViewTransition`（由 `src/instrumentation-client.ts` 在页面可交互前装上；2026-10-28 前装在 Navigation 模块里，偶尔仍漏报，改为最早一刻安装，并按 name/message 判断而不靠 `instanceof DOMException`）：Chrome 现在把切走标签页时的中止写成 "…invalid state. Document hidden"，React 19.3 只认不带后缀的措辞，会把它报成可恢复错误；这里改回它认得的措辞。`navigation.spec.ts` 用挂起的图片请求测前者（去掉修复即失败），`tests/unit/viewTransitions.test.ts` 测后者。
- **收藏夹页**原先对每个参数做 key，翻页、排序、换列表都整块重建：列表栏和标题消失、主区空白约 150ms。现在列表栏属于 `(shelf)` 布局，列表数据在 `useCollections` 里共用；面板不再按参数重挂载，取下一批时上一批留在屏幕上、变暗（`data-stale`），到了再换。选择状态跟"哪一组、第几页"绑在一起，换组或换页自然清空，不需要 effect。

**原文模式覆盖页面上每个名字**（2026-10-07）：凡是有原文的名字都成对请求（作品 `title`+`alttitle`，人/公司/角色 `name`+`original`，标签/特征 `name`+`translation.name`），并经 `display()` 或 `ui/Name` 按偏好选一个。此前漏掉的：VN 页角色的声优、侧栏关联作品与发行商、发行版行里的制作方、截图分组标题；角色页的作品与声优；发行版页的作品与被取代的版本；发行版列表卡片；条件构建器的芯片与搜索结果。漏的原因多是 `fields.ts` 没请求原文字段，所以加新的名字时两样都要：字段成对请求，渲染走 `display`/`Name`。

**目录页的标签页**（2026-10-07，对照旧项目改；2026-10-21 补人员的配音作品）：人员有三栏——Credited on（`staff=`，只是 `vn_staff` 的署名：剧本、原画、歌曲等）、Voiced in（`v` 的 `seiyuu=`，配过音的作品）、Voiced characters（`c` 的 `seiyuu=`）。vndb 把配音放在 `vn_seiyuu`，与署名分表，所以声优的 Credited on 往往只剩几首主题歌（友永朱音 s83：署名 7 部全是 songs，配音 506 部）；此前没有 Voiced in，那几百部作品无处可见。配音作品多于署名作品时两栏配音排在前面，默认打开的就是它。制作方有 Developed / Published / Developed or published / Releases。`CatalogPage` 把数为 0 的标签页去掉（全空时留第一个，好说"没有"）；与另一栏完全相同的也以 0 计而去掉：Developed or published 等于其中一边时、标签/特征的"直接"等于"含子项"时（直接的是含子项的子集，数相等即同一份）。只剩一栏时 `Tabs` 把它画成一个不可点的标签，页面仍说明列的是什么。

**剧透开关管住手动展开的内容**（2026-10-07）：`ui/Spoiler` 有 `SpoilerScope`（角色页描述、VN 页角色区的卡片与展开视图）；范围内的 `[spoiler]` 跟随该区的剧透级别——到"major"才显示（与 vndb 一致），以下隐藏，手动点开的只保持到级别改变为止。`VNCharacterCard` 的卡内特征展开同理：记着是在哪个区级别下展开的，区级别一变就作废。描述里带 `[spoiler]` 也算"有 major 剧透"，否则只有这种剧透的角色根本不出现开关。范围之外（如 VN 描述）仍是点一下就开。

**相似作品**（2026-10-03）：VN 页最后一段 Similar，`similar` 片段按列表卡片的同一组字段取（`fields.ts` 里由 `LIST.v.fields` 生成，两边不会走样），交给 `Results` 画卡片。2026-10-15 起是一行横滚（`vn/VNSimilar.tsx`，`Results` 的 `strip`）：20 张封面排成网格会是全页最长的一段，而封面是用眼睛扫的；段标题右侧有左右箭头，每次翻大约一屏，两端到头时变灰，滚轮、触控板和手指也照样能滑。`strip` 只对带图的类型生效，名字为主的类型仍是行列表。

**分面计数**（2026-10-15）：`FilterBar` 的每个筛选菜单打开时，用 `lib/api.ts` 的 `facet` 问一次 `/facets/{type}/{filter}`，把每个选项"选上后会剩多少条"显示在右侧；带的是地址里其余的筛选（`lib/href.ts` 的 `filtersOf`，列表页与条件构建器的预览计数也用它），该筛选自己的当前取值由 API 搁开。结果按请求缓存在菜单里，地址变了才重问；为 0 的选项变暗但仍可点；问不到就照旧只有选项。

**搜索只有一条结果时直接跳转**（2026-10-15）：`/q` 七类合起来只命中一条时直接去那一条，学 vndb；只在七类都答上来时才这样做，有一类出错就可能漏了第二条。

**ShelfPanel**（`components/user/ShelfPanel.tsx`）是收藏夹与评分页共用的面板，`CollectionPanel` / `RatingsPanel` 只提供数据源（`ShelfSource`：分页取、全量取）、自己的排序、批量操作条。排序分两类：用户服务自己知道的（收藏时间 `added`、我的评分 `mine`、评分时间 `rated`）由它排好、分好页，读 API 只补这一页的内容；读 API 的字段排序则把全部 id 交给读 API 排、分页。地址里的排序值不能与读 API 的重名（读 API 有自己的 `rating`），所以自己的叫 `mine`，`OwnSort.by` 才是用户服务的名字。带搜索时，用户服务的排序下由读 API 只回答哪些匹配（`fields=id`），顺序仍是用户服务的。卡片上显示我的评分（`Rated`：网格右上角、行左侧）。2026-10-23 拆成四块：读一页的逻辑在 `lib/shelf.ts`，批量选择在 `hooks/useShelfChoice.ts`，评分角标、缺失说明与列表内搜索在 `user/ShelfParts.tsx`，`ShelfPanel` 只剩组合（509 行 → 约 250 行）。

**批量选择跨页**（2026-10-22）：`ShelfPanel` 的选择原先按"列表 + 页码"记，翻页即清空；现在只按列表（`sourceKey`）记，翻页、换排序、搜索都保留，换到别的列表才结束——与结果页的 `Collecting` 一致。"选本页"只把这一页加进或移出，别页选的不动。因为选中的可能不在眼前，移除与清除评分的确认改成带数目（"Remove 3?"、"Clear 3?"）。

**未登录时**（2026-10-18）：收藏夹索引、具体列表、评分页、账号页、管理页统一用 `user/SignInFirst.tsx`：居中的卡片，图标、一句标题、一句说明，下面"Sign in"与"Create an account"两个按钮，都带 `?next=` 回到原页。原先各页各写一个左对齐的小框，只有一个登录文字链接。

**vndb 已移除的条目**（2026-10-01）：列表只存 id，镜像每天重建，vndb 隐藏或删除的条目会查不到。`hydrate`（现在在 `lib/shelf.ts` 里）不再把它们滤掉，而是换成 `GoneRow`（`lib/types.ts`，`{ id, gone: true }`）；`Results` 遇到它画 `GoneCard`（`ResultCards.tsx`：不是链接，网格里是同尺寸的虚线框，行列表里是一行灰字），照样能被勾选、移除或移到别的列表。按添加顺序时它们留在原位、计入总数；按 vndb 的字段排序时读 API 排不了它们，`whole.items.length - answer.count` 就是缺了几条，页面上一行说明并给出"回到添加顺序"的链接。`Results` 顺带改成按类型查表（`SHAPES`：有无图片比例、画哪种卡），封面与立绘的比例常量 `COVER` / `PORTRAIT` 由 `ResultCards` 导出，占位卡与真卡共用。

**卡片上显示排序所用的值**（2026-10-29）：`Results` 收 `sort`（`ResultsPanel` 传 `data.sort`，收藏夹传当前用的顺序），交给卡片。作品卡总有日期与评分，第三项按 Length 排序时是时长（`shortLength`：有玩家计时用小时，否则 vndb 的长度分档），其余排序是票数（`compactCount`，悬停看全数）——票数说明评分有多可信，是标题、日期、评分排序时最可能想看的。角色卡在性别后按 Age / Height 排序时加年龄 / 身高，并总有一行出自的作品（`lib/characters` 的 `mainWork`：出场不算剧透的作品里定位最重的）。发行行的标题与日期本来就在，补上语言图标（来自 `titles.lang`，机翻的半透明）。制作方、人员、标签、特征的排序字段本来就在卡上。收藏夹与评分页：`Owned` 带上 `at`（收藏或评分的时间），`OwnSort.dated` 的顺序（Added / Rated on）在卡上显示那天，与评分星一起由 `user/ShelfParts` 的 `Mine` 画（网格在图上右上角竖排，行列表在名字前并留出位置）；`Mine` 总包在卡外，换顺序不重建卡片。`lib/list.ts` 的字段清单相应加了 `length`、`length_minutes`，角色的 `age`、`height`、`vns.*`，发行的 `titles.lang`、`titles.mtl`。

**从结果页收藏**：`ResultsPanel` 包在 `results/Collecting.tsx` 的 `Collecting` 里，排序行右端多一个 `SelectToggle`（登录才出现；窄屏上排序行本来隐藏，靠 `has-[[data-select]]:block` 只为它显示）。点了之后 `Results` 从 context 得知正在选，卡片外的 `Selectable`（与 `/u` 同一个勾选卡片）便显出勾选框。`Selectable` 不论选不选都包在卡片外，不选时是 `display: contents`、不占版面（2026-10-28；此前开始选择时才包上，卡片上面的树变了，React 重建每张卡片、封面重新加载淡入，看起来全部闪一下，`tests/components/select.test.tsx` 守着卡片节点不变），底部出现保存条：选本页、计数、"Save to…"（该类型的列表 + 新建列表，新建即存入）、完成。选择**跨翻页保留**（`Collecting` 是客户端组件，软导航不重置）。保存条与 `/u` 的批量条共用 `user/SelectBar.tsx` 里的 `ActionBar` 外壳。`/q` 每个类型段各包一个 `Collecting`；模块级的 `stopCurrent` 保证同一页只有一组在选，不会叠出两条保存条。用户服务的出错文字统一由 `lib/user.ts` 的 `errorText` 给出。

**`<main>`**：列表页（`ListPage`）与所有详情页（`DetailShell`）的外层都是 `<main>`，与其他页面一致。

**结果上方的控件行**（`ResultsPanel`，2026-10-28）：放得下时一行；放不下时（按控件行自身宽度的容器查询，`@container`，阈值 68rem）各组一行竖排、标签统一宽度对齐，而不是几组几组地折行；手机上也是这三行（用户 2026-10-28 在几种排法里选定）。页面自带控件时（首页），竖排后 Select 单独一行、靠右，紧挨在结果上方；没有自带控件的页面它仍在排序行右端。窄屏（<640px）的排序下拉前面也有 "Sort" 标签、样式与已选的胶囊相同（`SortMenu` 的 `labelled`），与上面两行对齐；列表页工具栏里的排序下拉不变。控件行有 `relative z-10`：它自己的过渡层与容器查询都让它成为层叠上下文，不抬高的话月份、排序的下拉菜单会被后面的卡片盖住。首页的月份标签按最宽的月份（September）占位，换月份时箭头与后面的控件不再左右移动。

**窄屏的列表控件**（<640px）：筛选胶囊会折成三行，所以 `FilterBar` 在窄屏改成一行工具栏——"Filters · N"按钮（展开为每个筛选一行、带当前取值的面板，末尾是 Conditions 与 Clear all）加 `SortMenu`（排序与升降序合成一个下拉）；已生效的筛选在下面单独一行。列表页因此让 `ResultsPanel` 在窄屏隐藏它自己的排序行（`sortMenu={false}`）；目录页不传，`SortLinks` 在窄屏自动换成 `SortMenu`。条件构建器底栏的 Tidy / Text 在窄屏只显示图标。≥640px 一切照旧。

**保存搜索**（2026-10-17）：列表页搜索框旁的 `list/SavedSearches.tsx`（窄屏只有书签图标）。一个搜索就是列表页地址去掉页码后的查询串（`lib/searches.ts` 的 `queryOf`），所以打开它就是一个链接。登录后上半是账号里这一类型的命名搜索（每次打开都重读，别的设备刚存的也看得到；当前地址对应的那条高亮；可删除），当前地址有条件又没存过时末尾是"Save this search"——复用"新建列表"的 `ui/NewList.tsx`，文字由 props 换掉；未登录时是一块去登录的提示，登录后回到当前搜索。下半是本机最近搜索（只有排序、没有筛选的不算），不进账号。

**触屏的点按区域**：`coarse:` 变体（`@media (pointer: coarse)`）只在触屏生效。小链接与按钮加 `coarse:py-1`（行内链接的内边距只扩大点按区域、不挪版面），使点按高度到 24px；鼠标下的紧凑版面一点不变。搜索框里的 `<input>` 用 `py-1.5 -my-1.5` 撑满整个胶囊，点胶囊任何位置都能聚焦。新写的小链接 / 按钮照此处理。

**占位与正文换节点**（2026-10-16）：收藏夹索引、收藏夹面板、账号页都是"先画占位、会话或数据到了再画正文"。占位和正文若是同一种元素、在同一位置，React 会复用节点，浏览器便把它记成同一个元素移动加变高，算进 CLS（收藏夹 0.11）。所以占位与正文各带不同的 `key`，正文是新出现的元素，不算偏移。收藏夹索引另外改成数据到齐前只有一整块占位，不再先给每类各画一行。`ui/Collapsible` 同理：折叠从服务端渲染就生效，"Show more"叠在被折叠区域底部的渐隐上，不占额外高度；展开后才放到下方（那是读者自己点的）。

**键盘与滚轮**（2026-10-17）：`layout/Shortcuts.tsx` 挂在根布局里，`/` 聚焦搜索（先找正文里的，列表页就是列表自己的，再找顶栏的；都没有就去 /q），`←` `→` 翻页，`j` `k` 在段落导航的段落间跳，`?` 打开说明（"显示内容"菜单里也有入口）。每个键都是找到页面上做同一件事的控件去点它，所以键与点击的效果一样，没有那个控件的页面就没有那个键。打字时、有模态框（大图）开着时、或焦点所在的控件已经用掉这个键（`e.defaultPrevented`）时都不响应。行内选项用 `lib/rowKeys.ts`：标签页、分段选择、目录页标签都能用 ←→↑↓ Home End，按钮式的随焦点改选，链接式的只移焦点。角色轮播在焦点在其中时用 ←→。大图浏览加了 Home、End 与滚轮（每 250ms 最多一张）。`hooks/useSidewaysWheel.ts` 让竖向滚轮推动横滚的行（Similar、手机上的段落导航），到头即交还给页面。菜单的 Esc 改在捕获阶段处理并标记已处理，一次 Esc 只关最近的一层（不会连带关掉选择）；选择操作条也响应 Esc。目录页的 `results/Tabs.tsx` 因此成了客户端组件——服务端组件不能带事件处理，第一次改时整个制作方页 500，完整 e2e 才查出来。

**换页过渡**（2026-10-17）：根布局用 React 的 `<ViewTransition default="page">` 包住页面，每次站内跳转都是一次 View Transition：旧页 100ms 淡出，新页随后 240ms 淡入并上移 6px；顶栏有自己的 `view-transition-name`、叠在页面之上不动；收藏夹页左侧的列表栏（`.shelf-lists`，2026-10-22）也有：它在布局里、换列表时 DOM 本来就不动，但仍被截进页面那一层跟着淡出淡入，看起来整栏刷新了一遍。现在列表之间它只画新的一侧、不做动画（只有当前行的高亮变了）；从 /u 进来或回 /u 时它只在一侧（`:only-child`），随页面一起淡入淡出；`prefers-reduced-motion` 下直接切换。2026-10-28 起这套做法是一个 view-transition-class `still`（globals.css），`lib/viewTransitions.ts` 的 `still(name)` 给元素起名：首页的标题与计数、列表页的标题·搜索·筛选条与条件构建器、目录页（制作方、人员、标签、特征）的标题·侧栏·标签页、`/q` 的标题与搜索框、收藏夹与评分页的标题·标签页·排序与搜索行（`head/u/…`）、每个 `ResultsPanel` 的控件行（名字按路径取，不含类型：目录页换标签页时类型会变）也这样，翻页、换排序、换月份、换标签页、重新搜索时只有结果淡入淡出，控件当场换成新状态；去别的页时它们只在一侧，照旧随页面淡出。这些层各自是层叠上下文，所以带下拉菜单的放在下面内容之上：列表页的筛选区与目录页的标题 `z-20`，控件行 `z-10`。`DetailShell` 把侧栏画两份（宽屏在旁、窄屏在上），总有一份 `display: none`，过渡不截未绘制的元素，所以同名不冲突（宽窄两种宽度实测过渡都正常开始）。

页面那一层的框（位置与宽高）在旧页淡出期间停在旧页的框上，淡完一步跳到新页的框，不做插值（插值会把一页拉伸成另一页）。2026-10-18 之前是干脆不动画、一开始就取新页的框，慢放可见两处异常帧：快照按框的宽度绘制，/u 只有 3xl 宽、具体列表是整页宽，于是 /u → 列表时旧页被放大约 1.7 倍、反方向被缩小；从滚到底的页跳走时，新页回到顶部，旧页也被画成从顶部开始，淡出那一下跳回了开头。改后旧页留在原处淡出，但滚过的旧页会伸到顶栏底下，所以顶栏单独成层叠在上面。没有用"整页只截根快照"的办法：React 在顶栏没变时会取消根快照。`shelf.spec.ts` 与 `navigation.spec.ts` 用 `transition.ts` 的 `midway` 各测一种，改回旧样式两条都失败。原先各页 `main` 上的 `animate-slide-up-fade` 去掉了，不然新页会滑两次；弹出层（菜单、选择条、快捷键说明）的保留。导航时结果区变暗仍在，过渡从变暗的旧页开始。

**选择时给操作条留位置**（2026-10-17）：`ui/Selection` 的操作条浮在窗口底部，开着时给 `<html>` 加 `data-selecting`，`globals.css` 据此给窗口与各滚动栏末尾留 6rem，最后一行的翻页链接能滚到它上方（之前被它压住）。

**角色页的出场作品按作品合并**（2026-10-16）：读 API 的角色 `vns` 与 vndb 的 API 一样按发行版各给一条，`lib/characters.ts` 的 `byWork` 把同一部作品合成一条（最重的定位、最轻的剧透；只在部分发行版里出场时列出那几版），出场列表、段落计数与剧透范围都用合并后的。VN 页角色区被剧透藏起的角色从占一整格的卡片改成网格下方的 `SpoilerReveals` 胶囊，与标签区、出场列表一致；角色卡上的定位改成左下角的深色小徽标。

**视觉检查**（2026-10-15，宽屏 1440 与手机 390 各截全站主要页面）：发行列表的标题曾随前面平台图标的个数左右错开，平台挪到行尾后对齐；手机上发行列表的日期与年龄两栏挤得标题只剩几个字，改成标题独占一行、日期年龄平台放第二行；标签与特征列表在手机上收起分类一栏，让描述有地方；特征列表的 "sexual" 红字换成与标签列表一致的分类名；标签描述里漏出的 `[URL=…]`（BBCode 大小写，见 lib 表）；目录页 "Refine in …" 比内容右缘缩进 12px；`/q` 各段标题换成全站的 `Section`；`Section` 的数量加千位分隔。

**图标与文字对齐**：flex 居中对齐的是行框，而这套字体里混合大小写文字的视觉中心（x 高与大写高之间）比行框中心低约 0.1em，全大写低约 0.04em（实测 12/16/24px 一致），所以图标会显得偏高。挨着文字的图标加 `icon-text`（全大写标签旁用 `icon-caps`），定义在 `globals.css`，用 `translate` 所以能和 `rotate-180` 叠加；纯图标按钮不加。方向箭头一律用图标（`ArrowDown` 等），不用 `↓` 这类字符。

**雪碧图上色**：vndb 的雪碧图是给浅色页面画的。性别、发行类型（complete / partial / trial）、配音这几类是深色线条或几像素的小方块，在本站深色底上几乎看不见，所以 `icons.css` 把雪碧图当 `mask-image` 用，只取形状，颜色由 `background-color` 给：男蓝、女粉、双性紫、非二元黄、模糊黄绿、无性与未知灰；发行类型绿 / 紫 / 红（放大一倍）；配音沿用 vndb 的含义，红无、橙仅 H 场景、黄部分、绿全程。平台和语言图标本身是彩色标志，照旧直接画。

## 四、已知缺口

| 问题 | 现状 |
|---|---|
| 所有页面都是动态渲染 | 根布局读偏好 cookie（见总览），每次访问都在服务端完整渲染，只有 `fetch` 的 60 秒数据缓存。负载高时 Node 渲染会是瓶颈 |
| 目录页三轮串行请求 | 实体 → 各标签页计数（并行）→ 当前标签页的结果。要先有计数才知道默认开哪一栏，后两轮合不起来 |

### 踩过的坑（2026-09-17）

- **dev server 必须放行边缘的来源**。Next 16 默认拒绝非本源访问开发资源，经边缘访问时来源是 `127.0.0.1:17030`，热更新 socket 被拒 → dev 客户端起不来 → **整页不水合**：图片下完了但不显示，顶栏也不知道谁登录了。`next.config.ts` 里的 `allowedDevOrigins` 就是为此；生产构建不读它。除 localhost 外它还**自动放行本机的所有网卡地址**（2026-10-08：手机经局域网地址 `192.168.0.173:17030` 访问时页面不水合，文字有、图片不显示、不能登录），另可用 `NEOVNDB_DEV_ORIGINS`（逗号分隔）加别的主机名。服务端日志原话是 `Blocked cross-origin request to Next.js dev resource /_next/hmr`。
- **HTTP 200 证明不了页面能用**。上面那个问题期间，页面、图片、API 全部 200。`start.ps1` 的健康检查同样只看状态码，查不出水合失败——要确认前端真的活着，得在浏览器里看（元素上有没有 `__reactFiber` 键）。
- **图片可能在水合前就加载完**，见 3.4。这不是 dev 专属：生产构建下缓存命中时一样会发生。
- **滚动盒两个方向都裁剪**。`overflow-y:auto` 会让 `overflow-x` 也算成 `auto`，贴着滚动盒边缘的元素，其 ring / 焦点框伸出去的那部分会被切掉。修法是内边距 + 等量负外边距；**定宽的盒子还要补等量宽度**，否则左移会把右边缘和旁边那一栏一起带走——第一次修的时候就漏了这一步，主栏整体左移了 4px，靠对照已提交版本的像素坐标才发现。

- **滚动条出现或消失会让整页横移**（2026-09-18）。本站滚动条宽 8px，居中布局因此移动 4px。`/u` 的列表是客户端取的，长列表一到，页面滚动条出现，主体和顶栏一起左移——实测 CLS 0.0025。`html` 上加 `scrollbar-gutter: stable` 后为 0。两栏页面的每一栏也各自保留槽位：侧栏在 VN 页会滚动、在制作方页不会，不保留的话同一个侧栏在不同页面宽度不同。

### 已量过、不是问题

- **CLS**：必须在节流（Slow 4G）下量。回环网络上 `/me` 在首屏前就回来了，量出来恒为 0，具有误导性。节流后曾测得 /v17 0.0258、/u/98 0.0834、/u 0.0056，均已修到 ~0。
- **占位高度要照着真实构成算**：/u 的占位曾按文字高度估，结果把 CLS 从 0.0056 改成了 0.0224——那一行的高度其实由图标按钮决定。
- **响应式探针要探进滚动容器内部**：`overflow-y:auto` 会让 `overflow-x` 计算成 `auto`，只看最外层会漏掉 1024px 下侧栏溢出。
- **打开"原文"曾造成全站最大的一处重排**（0.1676）：服务端按默认值渲染英文，偏好在水合时才到。改存 cookie 后实测 0。
- **译名不会撑破版面**：最宽的日文标签 180px，最宽的英文 240px；只有 trait 分组标题变宽（106→113px），而那一栏是 128px。

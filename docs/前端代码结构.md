## 一、总览

Next.js 16.3.4（App Router）+ React 19 + Tailwind 4，TypeScript。约 10,800 行。

三条贯穿全局的约束，决定了目录为什么长这样：

- **列表状态全在 URL 里**。筛选、排序、翻页、标签页都是 query string，没有一个存在组件 state 里。因此任何一屏都可以直接粘贴链接复现，后退键行为天然正确，服务端渲染也不需要知道客户端有什么。
- **能在服务端渲染的就在服务端渲染**。详情页和列表页是 async server component，直接 `await` 取数；只有真正需要读浏览器状态的那一小块是 `"use client"`（原文开关、剧透等级、收藏按钮、图片灯箱……）。
- **偏好存在 cookie 里，服务端渲染时就知道**。`usePrefs` 仍是模块级 store（`useSyncExternalStore`，跨标签页共享），但"服务端快照"来自根布局从 cookie 读出、经 context 传下来的那份值——首屏与水合用的都是它。曾经它返回的是默认值，于是开着"原文"的读者每进一个页面都要看整页从英文改写成日文：实测 CLS 0.1676，全站最大。代价是三个原本静态的页面变成动态（偏好属于某个读者）。

### 取数路径

```
浏览器                                     服务端（Node）
  │ fetch("/vndbserve/vn?...")               │ fetch(NEOVNDB_API_BASE + "/vn?...")
  ▼                                          ▼
       Caddy :17030  ──►  backend/vndb :17031
       （两条路都过边缘，不存在"只在本地能用"的第二套地址）
```

前端只读两个环境变量，见 `frontend/.env.sample`：`NEOVNDB_API_BASE`（服务端取数走哪个边缘）与 `NEXT_PUBLIC_NO_IMAGES`（`start.ps1 -NoImages` 设置，构建时读入）。

`lib/api.ts` 是唯一出口，`lib/user.ts` 是用户服务的唯一出口。**页面要什么字段写在 `lib/fields.ts` / `lib/list.ts`**，不写在组件里——一个页面的代价因此是一处可读的清单，两个页面也不会对共用组件需要什么产生分歧。

### 测试

`npm test` 跑单元测试，`npm run test:watch` 盯着跑，`npm run typecheck:tests` 给测试做类型检查（根 `tsc` 不看 tests/）。`npm run test:e2e` 跑端到端，要先 `start.ps1` 把站起来；单元测试文件叫 `*.test.ts`，端到端叫 `*.spec.ts`，两套运行器各认各的。**测试代码不进 `src/`**：`src/` 里没有任何文件引用 tests/，`next build` 也看不到它们。

`conditions.test.ts` 会读 `backend/vndb/internal/api/<type>/filters.go` 的筛选表，确认前端条件目录里的每个键后端都有——两边原本只靠注释"keep the two in step"。

组件交互（jsdom + Testing Library）还没有；需要时加在 `tests/` 下的新子目录，不改这里的结构。

## 三、逐模块

### 3.1 `app/` —— 路由

| 文件 | 职责 |
|---|---|
| `icon.svg` | 网站图标（Next 按约定生成 `<link rel="icon">`） |
| `layout.tsx` | `<html>`、自托管字体（Righteous 做字标，配 metric-matched 回退字体以免换字时跳版）、Header |
| `page.tsx` | 首页：按月列出发行，月份在 URL 里 |
| `[slug]/page.tsx` | **一个动态段分发全部实体与全部列表**。vndb 的 id 本身就说明了类型（`v17` 是 VN），再加 `/v/` 前缀等于说两遍；`/v` 不带数字就是"全部 VN"。App Router 里静态段优先于动态段，所以将来加 `/about` 不受影响 |
| `[slug]/rg/page.tsx` | 关系图，单独一屏 |
| `login/` `register/` `account/` | 账号三件套 |
| `u/page.tsx` | 收藏夹索引（改名、删除、新建） |
| `u/(shelf)/layout.tsx` | 单个收藏夹的布局：左边的列表栏属于布局，所以在列表之间切换时它不重画、不丢滚动位置 |
| `u/(shelf)/[id]/` | 单个收藏夹。不再按地址参数做 key：换页、换排序只换结果，标题与控件不动 |
| `u/ratings/` | 我的评分：独立页面（评分属于条目而不属于列表，所以旁边没有列表栏），按类型切换，批量设分或清除；入口在顶栏用户菜单的 Your ratings |
| `admin/page.tsx` | 管理页的壳，内容是客户端的 `AdminPanel`：服务端不知道是谁在看，三个服务的 `/admin` 路由只认管理员的 cookie（边缘把关）。未登录给登录链接，非管理员给"Administrators only"与授予命令。顶栏用户菜单里只有管理员才看得到 Administration |
| `api/page.tsx` | 读 API 的说明页，入口在列表页页脚（`DataAge` 的 "API" 链接）。内容取自后端的 `/meta/openapi`（由真正服务请求的字段表/筛选表/排序表生成），所以列出来的都能用；每个筛选的含义与取值写法从 `conditions.ts` 取，没进条件构建器的标 "text view only"。静态段，优先于 `[slug]` |

### 3.2 `lib/` —— 取数与纯函数

| 文件 | 职责 |
|---|---|
| `api.ts` | 与读 API 对话的唯一出口。`byId` / `list` / `openapi`；浏览器用相对路径，Node 用 `NEOVNDB_API_BASE`（默认走边缘）。`revalidate: 60` |
| `admin.ts` | 三个服务的 `/admin` 路由：读 API 的状态/更新/回滚/译文、图片镜像的预取、用户服务的账号与备份。与 `user.ts` 一样只在浏览器里用，出错沿用 `UserError` |
| `user.ts` | 与用户服务对话的唯一出口：注册、登录、会话、注销账号、收藏、评分；`errorText` 是全站统一的出错文字 |
| `fields.ts` | **每个详情页要哪些字段**。按页面版式分组书写，一页的代价一眼可见 |
| `list.ts` | **每个列表页要哪些字段、提供哪些排序** |
| `choices.ts` | 枚举字典 → 选项列表的唯一出口：`Choice` 类型、`choices(group, iconGroup?)`，以及语言、平台、人员性别三份共用列表。筛选条与条件构建器都从这里取，不再各写一份 |
| `filters.ts` | 筛选条上的快捷菜单（每类型几个常用筛选） |
| `conditions.ts` | **条件构建器的词表**：每个类型能用哪些筛选、各是什么值类型（枚举/布尔/数字/日期/文本/按 id/标签特征带阈值/关联）。键与后端 `api/<type>/filters.go` 一一对应，**后端加筛选时要同步**；没列进来的筛选仍可在文本视图里手写。另有 `asExpression`（把一组普通筛选拼成一个 `f=`）与 `relatedSearch`（`developer=(search=key)` 这种"与匹配者相关"的表达式），都经 `print` 生成，引号永远正确 |
| `expr.ts` | `f=` 表达式的前端解析与打印，**与后端 `query/expr.go` 同一套文法**（含引号内括号不计数）。取反的叶子折进运算符（`!a=1` → `a!=1`、`!a>=1` → `a<1`，后端语义相同）；打印时跳过没填完的条件。另有 `tidy`（整理：拍平、拆单项组、折叠取反、合并可列表的同名条件、去重；哪些筛选可合并由 `conditions.ts` 的 `TIDY_RULES` 决定）与 `switchAt`（切换两项之间的连接词并按优先级重新分组） |
| `types.ts` | `fields.ts` 里字段对应的响应形状。**字段没要就不该出现在类型里** |
| `href.ts` | 从当前 URL 生成下一个 URL（列表状态全在 URL 的落地处） |
| `results.ts` | 跑一页搜索，与画它分开 |
| `format.ts` | API 留给客户端的渲染规则，含 `display(name, original, showOriginal)` |
| `bbcode.tsx` | vndb 的 BBCode 方言渲染；裸 id（`v17`）自动成链；`[url=]` 只认 `http(s)://` 与站内 `/…`，其余只留文字；嵌套内容行内渲染（不会出现 span 里套 div） |
| `enums.ts` / `icons.ts` | 短码 → 人话 / 短码 → 雪碧图类名；组件里一律用 `iconOf(group, code)` 取类名（找不到给 ""），不再各自把 `ICON.X` 强转成字典。性别有两套：`CHARACTER_SEX`（生理，m/f/b/n，n 是"无性"）与 `GENDER`（性别认同，m/f/o/a：非二元 / 模糊）；人员只有 m/f，筛选用 `STAFF_GENDER` |
| `images.ts` | 一张图实际从哪里取：`imageURL`（原图）、`thumbnailURL`（vndb 自己的缩略图：宽于 256px 的封面用 `cv.t`、截图用 `st`，其余给原图）。小框用后者，大框与灯箱用前者 |
| `graph.ts` | 关系图的纯布局：`tidyEdges` 去掉每对关系反向的那一半，`layout` 做重心排序，`edgePath` 画线。**不碰 DOM** |
| `prefs.ts` | 偏好的形状、默认值、cookie 名与解析。**与 `usePrefs` 分开**，因为服务端也要读它 |
| `images.ts` 的 `IMAGES_OFF` | `start.ps1 -NoImages` 的开关：一张图都不取，盒子照原尺寸画 |
| `characters.ts` / `traits.ts` / `vn.ts` / `content.ts` / `months.ts` / `utils.ts` | 各自的小块纯逻辑；`traits.ts` 的分组顺序与性相关分组门禁是共用的，避免一处加了另一处忘了 |

### 3.3 `hooks/`

| 文件 | 职责 |
|---|---|
| `usePrefs.tsx` | 原文开关、性/暴力内容等级、各区剧透的起始等级、角色区版式。模块级 store + `useSyncExternalStore`，跨标签页共享 |
| `useSession.ts` | 谁在读，以及注册、登录、登出、全部登出、改密码、注销账号，和服务端已说会话失效时的本地 `forget`。**只在 `status === "unknown"` 时接受第一份答复**——实测过一次竞态：登录前发出的 `/me` 回来晚了会把已登录状态覆盖回去 |
| `useSpoilerLevel.ts` | 某一区的剧透等级。控件待在有剧透的那一区；**起始等级**来自 prefs（顶栏可改），读者动过的区在本页内保留自己的选择，没动过的跟随偏好 |
| `useMenu.ts` | 弹出菜单的共用行为：`useMenu(open, setOpen)` 返回 `box`（点外面或 Esc 关闭；方向键 / Home / End 在菜单项间移动焦点）与 `panel`（贴边时推回屏幕内）。开合状态由调用方持有，因为有的菜单不只是切换（如收藏按钮先加载再打开）。全站 8 个菜单都用它 |
| `useArrowKeys.ts` | 方向键在 `panel` 的可聚焦项（链接、按钮、输入框）间移动，首尾循环；从开关按钮按 ↓ 落到第一项。数字框的 ↑↓ 与文本框的 Home/End 留给输入框自己。条件构建器的 `Popover` 也用它，所以整个构建器可以只用键盘操作 |
| `useDismiss.ts` / `useKeptOnScreen.ts` | `useMenu` 的几块，也可单独用：点外面或按 Esc 关掉的浮层；把展开的菜单留在屏幕内（直接写 `transform`，见 3.4）。量宽度用 `document.documentElement.clientWidth` 而**不是** `innerWidth`：页面始终保留滚动条槽位，按 `innerWidth` 算会把菜单右缘放到滚动条底下被裁掉（Windows 常见的 17px 滚动条下实测出现过） |

### 3.4 `components/ui/` —— 通用件

`ImageWithFallback` 挂载时会**主动检查 `<img>` 是否已经加载完**。缓存里的图、或者边缘直接从磁盘吐出来的图，常常在 React 水合之前就加载完了——那时 `onLoad` 还没挂上，load 事件落空，状态永远停在"加载中"，图片永远 `opacity-0`。状态同时带着它所属的 `src`，换图时从"加载中"重新开始，而不是继承上一张的"失败"（失败态不渲染 `<img>`，也就永远不会再试）。

`DetailShell` 的两栏与 `/u` 的两栏都是各自滚动的滚动盒：左侧各留 4px 内边距、再用等量负外边距抵消，定宽的一栏再补等量宽度；并且**始终保留滚动条槽位**（`scrollbar-gutter: stable`）——详见第四节。`/u` 的加载占位与加载完成后的面板共用同一组栏样式常量（`ROW` / `LISTS` / `BODY`），两者不可能对不齐。

`Name`（按偏好选脚本/译名）、`Description`（长文的同一件事）、`DetailControls`（七个详情页共用的一行控件：页面自带的 → 评分 → 原文开关 → 收藏）、`InfoCard`/`Section`/`Segmented`/`TabBar`/`Tooltip`/`Collapsible`/`Lightbox`/`Spoiler` 等。

`SearchPill` 是三处"提交才搜索"的圆角搜索框（列表页、收藏夹页、顶栏）的共同外壳，差异（前面的标签、后面的清除链接）走 `before` / `after`。`Selection` 是一次选多条的两件东西：盖在卡片上的勾选框 `Selectable` 与贴在窗口底部的 `ActionBar`；收藏夹页的"移动/删除"条（`user/SelectBar`）和结果页的"存入"条（`list/Collecting`）都往里放自己的按钮。`user/NewList` 是存入菜单底部的"新建列表"，收藏按钮与结果页存入条共用。

`Menu` 是全站弹出菜单的共用零件：`MenuPanel`（面板：按内容定宽，10–18rem；统一的边距、滚动上限与淡入）、`menuItem()`（行的样式，行本身仍是 `Link` 或 `button`——链接能在新标签页打开，按钮不能，这个区别不能被抹掉）、`MenuMark`（**多选是复选框，单选是单选圈**，读者点之前就知道点了是"加上"还是"换成"）、`MenuLabel`、`MenuDivider`。原先七个菜单各抄一份面板样式，宽度、边距、滚动上限各不相同。

淡入动画用 `translate` 而不用 `transform`：`useKeptOnScreen` 通过直接写 `transform` 把贴边的菜单推回屏幕内，动画若也动 `transform`，播放期间会覆盖它、播完再横跳一下。两个属性是叠加的。

`Trouble` 是"没东西可给、只有一个理由"的那种页面的共同形状：找不到和出错是同一个页面换套说法。

**内容分级、剧透起始等级与原文开关只在顶栏**（`ViewMenu`）。它们原先散在首页、列表页与四种详情页的侧栏里，收藏夹页反而够不到。注意 `DetailControls` 因此失去了首屏就占位的那个元素——评分与收藏都要等会话——所以那一行改用 `min-h-7` 自己撑住高度。

`ControlLabel` 值得单说：一排选项前面那个词（"Sort"）必须和选项本身长得不一样，否则会被当成选项之一——实际发生过。

### 3.6 其余 `components/`

按区域分目录，每个文件顶部的注释说明它负责哪一段版面，见上方文件树。`vn/` 最重，一个 VN 页拆成信息栏、标签、角色（网格/轮播两种版式）、发行、人员、截图、关系七块。

条件构建器在 `list/conditions/`，按职责分文件，依赖只朝一个方向（sentence → menus / editor → parts / context），没有环：

| 文件 | 职责 |
|---|---|
| `ConditionBuilder.tsx` | 面板本身：状态、文本视图、底栏（Tidy / Text / Clear / Apply）、实时命中数 |
| `context.tsx` | 树的编辑（`update` / `prune`）、共享的 builder context、同一时刻只开一个的 `Popover` |
| `sentence.tsx` | 芯片句子：`Flow`（一组条件与连接词）、`Connector`、`SubGroup`、`Chip`、`Summary` |
| `menus.tsx` | 组的模式菜单、添加菜单、筛选列表（Properties / Related 两段）、类型图标 |
| `editor.tsx` | 单个条件的弹出编辑器与各类取值编辑 |
| `useCondition.ts` | 取条件定义；外链站点条件在这里换成按类型过滤的枚举（站点清单每页取一次） |
| `entity.tsx` | 弹出层里的按名搜索 `EntitySearch`，与芯片上显示名字的 `useEntityName`（页内共享缓存） |
| `text.ts` / `parts.tsx` | 芯片文字的纯函数；共用的小件（搜索框、Done、删除按钮） |

树的编辑都走 `edit(key, fn, then)`，`then` 指定改完后打开哪个弹出层（`leaf<key>` / `add<key>` / `mode<key>`）；每次提交会**剪掉没填完的条件和空组**（正在编辑的除外），所以半截的条件不会进入 `f=`。

外链站点条件（`kind: "site"`）的选项来自 `/meta/extlinks`，每页取一次、所有芯片共用；芯片里 `useCondition` 把它换成按当前类型过滤的普通枚举，之后的编辑、多选、整理都不用另写。

取值的种类（`ConditionKind`）决定编辑器与可用比较：有序枚举（`ordered`，如动画程度）和分辨率（`resolution`，`1920x1080`）可以 ≥ / ≤，普通枚举只有是 / 不是；数字可带单位（`unit`，芯片上显示为"≥ 600 min"）；`credit` 是"某人 + 可选职位"（`s224:scenario`，`readCredit` / `writeCredit` 读写），编辑器先按名搜人、再选职位。

能装括号条件的由 `nestable` 判断（`relation` 与 `scored`，即标签/特征也能 `tag=(search=school)`）：编辑器给它们同一组四个模式（是这个 / 不是这个 / 有一个满足… / 没有一个满足…），芯片句子与"整理"都按它进到目标类型。

条件分两类：`conditions.ts` 的 `relatedType` 判断一个条件是否指向别的类型（`relation` / `entity` / `scored` / `credit`），构建器据此把添加菜单分成 Properties / Related 两段、给关联芯片加类型图标（`TYPE_ICON`）、让嵌套块换成天蓝色。

**不要用原生 `<select>`**：暗色页面里它弹出白底、看不见选项。选项一律用 `Menu` 的弹出层。

**页面宽度**：顶栏与所有页面共用 `max-w-page`（`globals.css` 里的自定义 utility：80rem，屏宽 ≥96rem 时 100rem），保证顶栏与内容对齐，改宽度只改一处。列表网格在 `2xl` 加到 7 列，卡片大小基本不变。

**翻页**：`Pagination` 画首尾与邻近几页，中间的"…"是 `PageJump`：点开变成页码输入框，回车跳转，超出范围的数夹到首页或末页（表单 `noValidate`，否则浏览器会因 `max` 拦下提交），Esc 或失焦收起。

**管理页**（2026-10-01）：`components/admin/`。Mirror 标签同时读三个服务的状态（各自失败各自显示），有任务在跑时每 2 秒跟一次、否则只读一次；按钮：Check now（立即更新）、Roll back…（二次确认）、Crawl now、Back up now。Translations 标签按 tag / trait 列出条目、默认只看缺译文的、可搜索；每个名字和描述各自保存（空串即删除），描述丢了标记服务端回 400 并显示原因；Export corpus 直接下载 init.json。Users 标签列出账号，自己那一行没有操作。时间按读者本地时钟显示到分钟，Go 的时长（`24h0m0s`）显示成 `1 day` 这样。

**过渡**（2026-10-03）：先实测了各种跳转（标记关键元素，逐帧采样），再按结果改：
- **服务端渲染的页面**（列表翻页、排序、筛选、目录页的标签页、首页换月、搜索）本来就只换内容，但从点击到新内容有 0.2–0.35 秒毫无反应。`components/layout/Navigation.tsx` 挂在根布局里：捕获阶段监听站内链接的点击（`next/link` 会 preventDefault，所以必须在它之前），程序化跳转走 `useNavigate()`；等过 120ms 还没到，顶上出一条细进度条，同时给 `<html>` 加 `data-navigating`，带 `data-results` 的结果区淡到一半（globals.css）。地址一变就结束，并把所有 `data-scroll-top` 的容器滚回顶部——宽屏下详情/目录页的内容栏、收藏夹的主栏是自己滚的，原先翻到第二页还停在页面中间（实测 626px）。
- **收藏夹页**原先对每个参数做 key，翻页、排序、换列表都整块重建：列表栏和标题消失、主区空白约 150ms。现在列表栏属于 `(shelf)` 布局，列表数据在 `useCollections` 里共用；面板不再按参数重挂载，取下一批时上一批留在屏幕上、变暗（`data-stale`），到了再换。选择状态跟"哪一组、第几页"绑在一起，换组或换页自然清空，不需要 effect。

**目录页的标签页**（2026-10-07，对照旧项目改）：人员的第二栏是**配音的角色**（`type: "c"`，`seiyuu=`），不是作品；制作方有 Developed / Published / Developed or published / Releases。`CatalogPage` 把数为 0 的标签页去掉（全空时留第一个，好说"没有"）；与另一栏完全相同的也以 0 计而去掉：Developed or published 等于其中一边时、标签/特征的"直接"等于"含子项"时（直接的是含子项的子集，数相等即同一份）。只剩一栏时 `Tabs` 把它画成一个不可点的标签，页面仍说明列的是什么。

**剧透开关管住手动展开的内容**（2026-10-07）：`ui/Spoiler` 有 `SpoilerScope`（角色页描述、VN 页角色区的卡片与展开视图）；范围内的 `[spoiler]` 跟随该区的剧透级别——到"major"才显示（与 vndb 一致），以下隐藏，手动点开的只保持到级别改变为止。`VNCharacterCard` 的卡内特征展开同理：记着是在哪个区级别下展开的，区级别一变就作废。描述里带 `[spoiler]` 也算"有 major 剧透"，否则只有这种剧透的角色根本不出现开关。范围之外（如 VN 描述）仍是点一下就开。

**相似作品**（2026-10-03）：VN 页最后一段 Similar，`similar` 片段按列表卡片的同一组字段取（`fields.ts` 里由 `LIST.v.fields` 生成，两边不会走样），直接交给 `Results` 画成网格。

**`<main>`**：列表页（`ListPage`）与所有详情页（`DetailShell`）的外层都是 `<main>`，与其他页面一致。

**窄屏的列表控件**（<640px）：筛选胶囊会折成三行，所以 `FilterBar` 在窄屏改成一行工具栏——"Filters · N"按钮（展开为每个筛选一行、带当前取值的面板，末尾是 Conditions 与 Clear all）加 `SortMenu`（排序与升降序合成一个下拉）；已生效的筛选在下面单独一行。列表页因此让 `ResultsPanel` 在窄屏隐藏它自己的排序行（`sortMenu={false}`）；目录页不传，`SortLinks` 在窄屏自动换成 `SortMenu`。条件构建器底栏的 Tidy / Text 在窄屏只显示图标。≥640px 一切照旧。

**触屏的点按区域**：`coarse:` 变体（`@media (pointer: coarse)`）只在触屏生效。小链接与按钮加 `coarse:py-1`（行内链接的内边距只扩大点按区域、不挪版面），使点按高度到 24px；鼠标下的紧凑版面一点不变。搜索框里的 `<input>` 用 `py-1.5 -my-1.5` 撑满整个胶囊，点胶囊任何位置都能聚焦。新写的小链接 / 按钮照此处理。

**图标与文字对齐**：flex 居中对齐的是行框，而这套字体里混合大小写文字的视觉中心（x 高与大写高之间）比行框中心低约 0.1em，全大写低约 0.04em（实测 12/16/24px 一致），所以图标会显得偏高。挨着文字的图标加 `icon-text`（全大写标签旁用 `icon-caps`），定义在 `globals.css`，用 `translate` 所以能和 `rotate-180` 叠加；纯图标按钮不加。方向箭头一律用图标（`ArrowDown` 等），不用 `↓` 这类字符。

## 四、已知缺口

| 问题 | 现状 |
|---|---|
| 没有组件交互测试 | 纯逻辑有单元测试，主要流程有端到端；CLS/响应式仍靠量 |
| 译文无法在界面里补 | 管理员界面已暂缓；补译文是改 `backend/vndb/internal/trans/init.json` 再 `neovndb trans seed`。特征已全部有译文 |

### 踩过的坑（2026-09-17）

- **dev server 必须放行边缘的来源**。Next 16 默认拒绝非本源访问开发资源，经边缘访问时来源是 `127.0.0.1:17030`，热更新 socket 被拒 → dev 客户端起不来 → **整页不水合**：图片下完了但不显示，顶栏也不知道谁登录了。`next.config.ts` 里的 `allowedDevOrigins` 就是为此；生产构建不读它。服务端日志原话是 `Blocked cross-origin request to Next.js dev resource /_next/hmr`。
- **HTTP 200 证明不了页面能用**。上面那个问题期间，页面、图片、API 全部 200。`start.ps1` 的健康检查同样只看状态码，查不出水合失败——要确认前端真的活着，得在浏览器里看（元素上有没有 `__reactFiber` 键）。
- **图片可能在水合前就加载完**，见 3.4。这不是 dev 专属：生产构建下缓存命中时一样会发生。
- **滚动盒两个方向都裁剪**。`overflow-y:auto` 会让 `overflow-x` 也算成 `auto`，贴着滚动盒边缘的元素，其 ring / 焦点框伸出去的那部分会被切掉。修法是内边距 + 等量负外边距；**定宽的盒子还要补等量宽度**，否则左移会把右边缘和旁边那一栏一起带走——第一次修的时候就漏了这一步，主栏整体左移了 4px，靠对照已提交版本的像素坐标才发现。

- **滚动条出现或消失会让整页横移**（2026-09-18）。本站滚动条宽 8px，居中布局因此移动 4px。`/u` 的列表是客户端取的，长列表一到，页面滚动条出现，主体和顶栏一起左移——实测 CLS 0.0025。`html` 上加 `scrollbar-gutter: stable` 后为 0。两栏页面的每一栏也各自保留槽位：侧栏在 VN 页会滚动、在制作方页不会，不保留的话同一个侧栏在不同页面宽度不同。

### 已量过、不是问题

- **CLS**：必须在节流（Slow 4G）下量。回环网络上 `/me` 在首屏前就回来了，量出来恒为 0，具有误导性。节流后曾测得 /v17 0.0258、/u/98 0.0834、/u 0.0056，均已修到 ~0。
- **占位高度要照着真实构成算**：/u 的占位曾按文字高度估，结果把 CLS 从 0.0056 改成了 0.0224——那一行的高度其实由图标按钮决定。
- **响应式探针要探进滚动容器内部**：`overflow-y:auto` 会让 `overflow-x` 计算成 `auto`，只看最外层会漏掉 1024px 下侧栏溢出。
- **打开"原文"曾造成全站最大的一处重排**（0.1676）：服务端按默认值渲染英文，偏好在水合时才到。改存 cookie 后实测 0。
- **译名不会撑破版面**：最宽的日文标签 180px，最宽的英文 240px；只有 trait 分组标题变宽（106→113px），而那一栏是 128px。

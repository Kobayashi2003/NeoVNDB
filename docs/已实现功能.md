## 一、镜像与导入

vndb 官方 dump → 本地 Postgres 的逐字镜像，外加一层只读 HTTP API。

| 项 | 状态 |
|---|---|
| 下载、校验（SHA256）、流式解 zstd+tar | ✅ |
| 42 张表按 dump 原样导入（`v17` → `17` 的列改写） | ✅ |
| 派生：标签/特征分数与继承展开、传递闭包、搜索索引、`c_*` 缓存列 | ✅ |
| 代次机制 `vndb` / `vndb_prev` / `vndb_next`，事务内原子换代，可回滚 | ✅ |
| 上线前熔断：行数缩水、表没导入、派生表为空；`-force` 可强过 | ✅ |
| `update` 一条命令跑定时与手动，上游没更新就什么都不做，且拒绝倒退 | ✅ |
| **内置定时更新**（2026-09-26）：`serve` 进程自己每 `NEOVNDB_UPDATE_EVERY`（默认 24h，启动后 `NEOVNDB_UPDATE_FIRST_AFTER` 默认 10m 第一次）跑一次 `update`，不再需要系统计划任务 | ✅ |
| 导入互斥：Postgres 咨询锁，定时更新与手动 import/update 不会同时跑，后来者报 "another run holds the lock"（实测持锁时被拒、放锁后通过） | ✅ |

## 二、读 API（`backend/vndb`，:17031）

| 路由 | 说明 |
|---|---|
| `GET /{type}` | 七种类型共用的查询端点：`f=` 条件表达式（`,` 或、`+` 与、`!` 非、括号；与扁平参数 AND），`fields` 选字段、`filters` 筛选、`sort`/`reverse` 排序、分页、搜索（**按词拆分、顺序无关**，引号内按原序，最多 8 个词）；`sort=searchrank` 按匹配质量排：完全相等 > 前缀 > 所有词同在一个名字里（按标题 / 别名 / 间接命中打折），再看相似度与人气（实测 `key` → Key、`fate` → Fate/stay night、`muv luv` → Muv-Luv 与 Alternative 居前，常规查询 5–35ms） |
| `GET /vn/{id}/relations` | 关系图：从一部作品向外走 N 步，每个点带深度、封面（尺寸与内容等级）、开发状态、评分。另回 `max_depth`（本服务允许的最深步数，0 为不限）、`reach`（返回的点最深在第几步）、`truncated`（后面还有）、`capped`（是节点上限截住的，加深也没用） |
| `GET /facets/{type}/{filter}` | （2026-10-15）分面计数：`?values=en,ja` 加列表的其余筛选，回每个取值选上后剩多少条；该筛选自己的当前值搁开。用的就是该筛选本身的条件，所以与选上后列表的总数逐一相等（实测 `length=3+lang=en` 下 Windows 947、PS4 110，与列表一致）。一条语句；不走缓存时 53 种语言全数 248ms，带条件 8–160ms；取值个数受 `NEOVNDB_MAX_FILTER_NODES` 限制。前端各筛选菜单的数量即此 |
| `GET /meta/fields/{type}` | 该类型的全部字段及其形状（前端与人都靠它自省） |
| `GET /meta/extlinks` | 全部 82 个外链站点及其显示名、会出现在哪些类型上 |
| 更多筛选（2026-09-24） | ✅ VN：`length_minutes`（实测时长，分钟）、`relation=fan`（有某类关联作品）、`credit=s224:scenario`（某人在**这部**作品里担任某职位，职位可省略）；发行版：`resolution=1920x1080`（也可 `>=` / `<=`，未知的 0x0 不参与比较）、`ani_story` / `ani_ero`（动画程度 1–4，可比较）；角色：`birthday=12-25` 或 `birthday=12`（整月）、`has_image`。非法值都给明确报错。实测与原始数据逐一对上（实测时长 16,995、1080p 11,668、全程动画 1,381、`ani_story>=3` 5,137、有立绘 157,746；Maeda Jun 参与 21 部、其中剧本 10 部、音乐 17 部）；嵌套可用："有 1080p 以上发行版的作品" `release=(resolution>=1920x1080)` 6,626 部。构建器里对应：播放时长（带单位）、关联、"Staff in a role"（选人后选职位）、分辨率、动画程度（有序，可 ≥ / ≤）、生日、有无立绘 |
| 外链与 DRM 筛选 | ✅ `extlink=steam`（v / r / p / s，未知站点报错）；发行版 `drm_free`（有 DRM 记录且无任何限制属性；没有记录的算"未知"，两边都不算）与 `drm_needs=online,account`（DRM 要求常在线 / 账号 / 联网激活……）。实测 `drm_free` 真 16,639 + 假 3,314 = 有 DRM 记录的 19,953；`extlink=steam` 11,575 与原始链接数一致；"有无 DRM 英文发行版的作品" `release=(drm_free=true+lang=en)` 10,119 部。构建器里对应"Has a link to"（站点清单来自后端，按类型过滤）、"DRM-free"、"DRM requires" |
| VN 的 `similar` 片段 | （2026-10-03）按标签相似的作品，每部最多 20 个，带 `score`（余弦，0–1），与它有关联的作品不算。导入时用 Go 计算（全库约 3 秒），存在每一代的 `vn_similar` 里。VN 页底部的 Similar 段即此；实测 Ever17 前几名为 Dei Gratia no Rashinban、Root Double、The Sekimeiya、9 Hours 9 Persons 9 Doors、I/O、AI: Somnium Files |
| `GET /meta/openapi` | （2026-09-26）OpenAPI 3.1 自述：由各类型真正服务请求的字段表、筛选表、排序表生成，不会与实际脱节；版本号是线上代次。实测 12 条路径，vn 36 个参数（29 个筛选、9 种排序）、27 个字段。前端 `/api` 页据此渲染，每个筛选附含义与取值写法，入口在列表页页脚 |
| `GET /meta/generation` | 当前线上代次 |
| `GET /health` | |

字段面：vn 27、release 26、character 25、trait 13、tag 10、producer 8、staff 8。每个字段在源码里都带取值方式标签（COL/CONV/CALC/DERIV/JOIN1/LIST/REL/MADE），可以直接对着 DDL 核。

客户端中途离开（如条件构建器的实时计数被新的一次取代）记 Info、回 499，不再记成 ERROR/500；超时回 504。

进程内 LRU 响应缓存（可换 Redis）。深翻页实测无退化：最后一页 11.7ms。

## 三、图片镜像（:17032）

- 回源 t.vndb.org，**只存原件，逐字节**
- **不做缩放**（2026-09-25）：缩略图全部用 vndb 自己的——封面 `cv.t`（只有宽于 256px 的封面才有，窄的原图本身就够小）、截图 `st`；立绘上游没有缩略图，直接用原图。原先的本地缩放、宽度白名单与派生目录（412 个文件、12 MB）已删除
- 要的缩略图上游没有时给原图，不落假文件
- single-flight：并发取同一张图只回源一次
- 已落盘的图由 Caddy 的文件服务器直接吐出，根本不进这个进程
- **cv.t**：vndb 自己的 256px 封面缩略图，与 `st`（截图缩略图）一样作为原件镜像；预取只取宽于 256px 的封面的 cv.t，不去问注定 404 的
- 2026-09-25 把旧服务的图片**移入**（同盘改名，不复制）：共 449,814 张（ch 85,288 / cv 86,008 / cv.t 37,132 / sf 120,753 / st 120,633），重复的 738 张保留新的、删除旧的；旧服务的 images 目录已清空删除。抽查旧文件与 vndb 上游逐字节一致
- **预取**：镜像每 `NEOVNDB_IMAGE_CRAWL_EVERY`（默认 1h，启动后 `NEOVNDB_IMAGE_CRAWL_FIRST_AFTER` 默认 1m 第一次）从库里的 `images` 表找出盘上没有的图（连同 cv.t / st 缩略图），新的先取，每轮 200 张、间隔 2 秒；`neovndb crawl [--limit n]` 手动跑。实测一轮取到 4 张、仍缺约 38.5 万张（默认速度约 80 天补齐，`--limit 0` 一次取完约 9 天）

## 四、用户服务（`backend/users`，:17033）

独立 Go module、独立数据库 `neovndb_users`——镜像的 schema 每周重建，账号不能放在旁边。启动时幂等建表。

| 能力 | 路由 |
|---|---|
| 注册 / 登录 / 登出 / 全端登出 | `POST /register` `/login` `/logout` `/logout-everywhere` |
| 当前账号、改密码、注销账号 | `GET /session`（谁登录着，未登录回 null，200）、`GET /me`、`POST /me/password`、`POST /me/delete`（要再输一次密码；收藏夹、条目、评分、会话随账号级联删除，并退出登录） |
| 边缘鉴权 | `GET /auth/verify`（回 `X-User-Id` / `X-Is-Admin`） |
| 登录/注册限流 | 按来源地址与按用户名各自滑动窗口计数，超出回 429 + `Retry-After`；登录成功清零；注册只对"真的在建号"计数，表单填错不计。来源取边缘追加的 `X-Forwarded-For` 末项。**次数与窗口都是配置项，0 即无上限；开发环境已放开** |
| 收藏夹增删改查 | `GET/POST /collections`、`PATCH/DELETE /collections/{id}` |
| 收藏条目：翻页、整表取、单条增删、批量加/删/移 | `/collections/{id}/marks`、`/items`、`/marks/{item}`、`/marks/add`、`/marks/remove`、`/marks/move`（批量加回报新加了几条，已在的不算） |
| 某个条目在哪些收藏夹里 | `GET /holding/{item}` |
| 评分（1–5，清除是 DELETE 不是 0 分） | `GET/PUT/DELETE /ratings/{item}` |
| 账号里的偏好（2026-10-17） | `GET/PUT /me/prefs`：前端发来的整个对象原样存，不认字段，≤2KB；从没存过回 `null` |
| 命名的搜索（2026-10-17） | `GET/POST /searches`（`?type=`）、`DELETE /searches/{id}`；同类型内名字唯一，查询串 ≤2048 字符。**每人条数上限 `NEOVNDB_USERS_MAX_SEARCHES`（样例 200，开发放开）** |

登录不再泄露用户名是否存在：未知用户名也做一次同等 cost 的 bcrypt 校验，响应时间与密码错误相同。

用户服务的存储层有了连数据库的测试：设 `NEOVNDB_USERS_TEST_DB_URL` 指向一个名字以 `_test` 结尾的库即运行（每次先清空，故名字不对就拒绝），不设则跳过。覆盖账号与起始列表、会话过期、列表只属于主人、批量加/删/移（保留收藏时间）、评分、注销账号的级联，以及账号里的偏好与命名的搜索（只属于主人、同类型重名被拒、条数上限）。

改密码与注销账号时的再验密码按账号计入登录尝试次数限制，拿到别人的会话也不能借此无限次猜密码。

账号规则：用户名只收 ASCII 字母、数字、`-`、`_`（此前全角与阿拉伯数字能混进来，与普通数字看起来一样）；密码 8–72 字节——此前上限写的是 128，而 bcrypt 超过 72 字节直接报错，73–128 字节的密码注册时会得到 500。

密码只有 bcrypt。会话是服务端的行，随时可删；会话 cookie 只认当前配置的那一个名字。

**旧数据迁移已完成且逐行核对**（3 个账号 / 25 个收藏夹 / 673 条收藏 / 1 条评分）。2026-09-25 按用户要求只保留 kobayashi（11 个收藏夹、676 条收藏），另两个账号（isnekoda、TEST，只有空的起始列表与 1 条评分）已删除，随之删掉对旧密码格式与双 cookie 名的兼容。

**定时备份**（2026-09-25）：用户服务每 `NEOVNDB_USERS_BACKUP_CHECK_EVERY`（默认 1h，启动后 `BACKUP_FIRST_AFTER` 默认立刻）检查一次，最新备份超过一周就 `pg_dump` 一份到 `data/backups/users/`，保留最新 8 份；`users backup` 立即备份。首份备份已生成并用 `pg_restore --list` 核对可读。


**管理页**（2026-10-01）：`/admin`，只有管理员能进（`users admin <name>` 授予；边缘用 `forward_auth` 问 `/auth/admin`，未登录 401、非管理员 403）。
- Mirror：线上与上一代的代次、发布与导入时间、库大小、译文条数；更新任务（上次结果、下次时间、输出末尾，运行中每 2 秒刷新）与 Check now；保留的归档；回滚（二次确认，持导入锁）；图片预取的覆盖率与 Crawl now；用户库备份列表与 Back up now。实测：Check now 导入并上线 20261001（4 分 57 秒），第二次点被 409 拒绝，上线后按 `NEOVNDB_DUMP_KEEP` 删掉了 4 份旧归档。
- Translations：标签/特征逐条显示英文与译文，默认只看缺的（当前特征 1 个名字、5 段描述缺译文），可搜索；名字与描述各自保存，描述丢了标记拒收；改动立即生效（推进 `trans.revision`）。Export corpus 下载 init.json，`neovndb trans export` 直接写回仓库里的那份。实测改一段描述、读 API 立即返回新译文，删除后导出与改之前逐字节相同。
- Users：账号、加入时间、列表/条目/评分数、会话与最近登录；设/撤管理员、强制登出、删除（二次确认）。不能作用于自己。

## 五、译文（`trans` schema）

vndb 的标签与特征只有英文，没有"原文"可切。本项目自备的译文放在生成 schema 之外，重新导入不受影响。

- `trans.terms` 5,726 条，`trans.passages` 6,361 条
- 覆盖（2026-09-25 实测）：**标签名 3,014/3,014、标签描述 3,011/3,011、特征名 3,327/3,327、特征描述 3,327/3,327，全部有译文**
- 语料本身在仓库里：`backend/vndb/internal/trans/init.json`（此前只在旧项目里有这一份）；`neovndb trans seed` 不带参数即载入它，重复执行安全；`go test` 会逐条校验这份文件的标记
- 2026-09-24 补齐特征：9 个新特征名、39 段描述（其中 33 段是 vndb 改过英文原文、旧译文按哈希对不上了，按新原文改译；6 段是新特征）；顺带改正一个误译：发型"Intake"原译"摂取"，改为"インテーク（髪の折り返し）"
- 改了译文立刻生效：`trans seed` 会推进一个版本号，它和代次一起组成响应缓存键的前缀，旧缓存整批作废
- 按文本内容做键，不按 id：换 dump 无需任何重解析
- `trans seed` 写入前全量校验 BBCode 与裸 id 是否原样保留，有一条不过就整份拒绝
- API：tag / trait 上的 `translation` 片段与 trait 的 `group_translation`
- 前端接在既有的"原文"开关上，标签页、特征页、角色页、VN 页标签、两个列表页全部实测过

覆盖率：标签名 99%、标签描述 98%、特征名 84%、特征描述 98%。没有译文的回落英文。

## 六、边缘（`edge`，:17030）

**唯一对外地址。** 四个服务都只听回环，任何一条 URL 在本地和线上都一样。

- `/vndbserve/*` `/imgserve/*` `/userserve/*` 三个前缀，各自一份路由白名单，白名单外直接 403 不转发
- 因此 `backend/vndb` 和图片服务里**一行鉴权代码都没有**——谁能调是边缘回答的问题
- 已在磁盘上的图片由 `file` matcher 直接命中，不进后端进程

## 八、运维

一键启动（PowerShell 7）：

```powershell
.\start.ps1 -Build     # 先编译两个 Go 二进制（带 -Prod 时连前端一起），再起全部五个进程并打开浏览器，Ctrl+C 一起停
.\start.ps1            # 同上，用现有的编译产物；缺了就提示加 -Build
.\start.ps1 -Prod      # 前端用生产构建（用 -Build 构建）而不是 dev server
.\start.ps1 -NoBrowser # 不自动打开浏览器
.\start.ps1 -NoImages  # 一张封面截图都不请求，方便在镜像不在手边时改代码
.\start.ps1 -Stop      # 停掉上一次留下的
.\start.ps1 -Force     # 端口被占就抢过来
```

`-NoImages` 下每张图的盒子仍按原尺寸画出来，所以在改的就是真实版面；界面自己的雪碧图图标（语言、平台）是本地的，照常显示。

三个服务的端口与图片目录从各自的 `.env` 里读，不写死在脚本里，并**交给边缘**（`VNDBSERVE_UPSTREAM` 等环境变量与两个图片目录的绝对路径）——改了 `.env` 里的端口或目录，边缘跟着走（此前边缘用的是自己的默认值，改端口会让它指向旧地址）。同名的真实环境变量优先于 `.env`，与服务自身一致。Next 与边缘默认 17034 / 17030，可用 `NEOVNDB_WEB_PORT` / `NEOVNDB_EDGE_PORT` 改；服务端渲染的 `NEOVNDB_API_BASE` 跟随脚本启动的边缘。端口被占默认**拒绝启动**而不是猜；每个服务都等到真的能应答才算数，没起来的会把日志末尾几行打出来；日志在各自目录的 `<名字>.out.log` / `.err.log`。

手动等价于：

```sh
cd backend/vndb  && go run ./cmd/neovndb serve
cd backend/vndb  && go run ./cmd/neovndb images
cd backend/users && go run ./cmd/users
cd frontend      && pnpm dev
cd edge          && caddy run          # http://127.0.0.1:17030
```

CLI：`serve`、`images`、`import`、`update`、`db status|init|check|promote|rollback|drop|verify`、`trans status|seed`；用户服务不带参数即运行（一次性的旧库迁移命令已在迁移核对完成后删除，留在 git 历史里）。前端脚本：`dev`、`build` / `start`、`lint`、`test` / `test:watch`、`typecheck:tests`。完整清单与说明见仓库根目录 `README.md` 的 Commands / Tests 两节。

配置：每个部分读自己目录里的 `.env`（不进 git），`.env.sample` 列出该部分读取的**全部**设置及部署该用的值——`backend/vndb`、`backend/users`、`frontend` 各一份（前端两项：`NEOVNDB_API_BASE`、`NEXT_PUBLIC_NO_IMAGES`）。边缘没有 `.env`，它的七个环境变量（监听地址、四个上游、两个图片目录）列在 `README.md` 的 The edge 一节，由 `start.ps1` 设置。

测试：`go test ./...`（两个 Go 模块）与 `pnpm test`（前端）都不需要起服务；用户服务的存储层测试要 `NEOVNDB_USERS_TEST_DB_URL` 指向名字以 `_test` 结尾的库，不设则跳过。

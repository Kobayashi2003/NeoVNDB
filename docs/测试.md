# NeoVNDB 测试

> 最后更新：2026-11-13
> 各套测试怎么跑、要什么、覆盖什么。加减测试文件时同步本文的清单。

---

## 一、怎么跑

```powershell
cd backend/vndb;  go test ./...
cd backend/users; go test ./...
cd frontend;      pnpm test                # 单元与组件测试
cd frontend;      pnpm test:e2e            # 端到端，对着运行中的站
cd frontend;      pnpm test:e2e:deployed   # 端到端，对着按上线配置另起的一套站
```

交接前的全套检查：

- 前端：`pnpm typecheck`、`pnpm typecheck:tests`、`pnpm lint`、`pnpm format:check`、`pnpm test`，以及构建——**站在运行时用 `NEOVNDB_NEXT_DIR=.next-check pnpm build`**（见下）。
- 两个 Go 模块：`gofmt -l .`、`go vet ./...`、`go test ./...`。
- `pnpm test:e2e:deployed`（刚构建过可加 `E2E_SKIP_BUILD=1`）；输出重定向到文件，不要接 `Select -First` 这类会提前掐断的管道，否则 teardown 不跑；跑完确认 17035–17038 没有残留监听。

## 二、要哪些库

| 环境变量 | 谁用 | 要求 |
|---|---|---|
| `NEOVNDB_USERS_TEST_DB_URL` | 用户服务的 `store` 与 `api` 测试、要登录的 e2e | 库名以 `_test` 结尾，否则拒绝运行 |
| `NEOVNDB_TEST_DB_URL` | 读 API 连库的测试：全年龄规则、整代构建与服务（`TestAllAges`）、导入的 COPY、半成品代次 | 同上；可与上一个是同一个库 |

不设就跳过，其余照跑。

- 用户服务的 Go 测试每条先清空表。`store` 与 `api` 两个包都会清，`go test` 又并行跑各包，所以两边先拿同一把 Postgres 咨询锁（`testLock`）排队。
- e2e 注册的 `e2e_…` 账号留在测试库里，不清。
- 读 API 的连库测试各在自己的 schema 里做、做完删掉（`TestAllAges` 建 `vndb` / `vndb_next` / `vndb_prev` / `trans`，测试库里已有 `vndb` schema 时拒绝运行）。
- 两个服务启动时都会建 `trans` schema，建之前拿一把咨询锁：几个测试包并行打开库时，`CREATE ... IF NOT EXISTS` 同时执行会撞唯一约束。

## 三、Go 测试

**读 API（`backend/vndb`）**

- `internal/api`：用服务真正运行的 catalog 编译跨类型嵌套条件；每个类型的每个筛选遇到坏输入都回 400 而不是 500；每个类型都能自述（OpenAPI）；`TestAllAges` 端到端（见下）。
- `internal/api/query`：请求解析、上限、缓存键（筛选值与 `f=` 都进键）、占位符编号、表达式、字段与成本、分面、遮罩（主查询的条件、`Relate` 去掉被挡的子实体、图片阈值）、描述检索拼出的 SQL（每词一个 `LIKE`、编号接在前面的参数后）。
- 各类型包：新加的专门筛选、关系图的步数与节点上限、推荐的参数解析、关系图遮罩后重算步数。
- `internal/db`：全年龄规则（`withheld_test.go` 在测试库里建临时 schema、跑真 DDL 与真 SQL，逐条验证规则两侧，事务回滚）；半成品代次读作"没有"；统计的译名填充；`trans.norm` 与 `search_norm_term` 的函数体一字不差（`search_test.go`）。
- `internal/importer`：被 Postgres 拒收的一行结束导入，而不是挂住。
- `internal/dump`：两种上游重定向形态、只认 `href` 里的档案名、未发布的档案报错、下载停住时放弃、清理被杀掉的下载、只留最新 N 份。
- `internal/img`：路径解析、原子写、并发合并、回源并发上限、缺缩略图给原图、重定向且后台取、上游 404 后不再回源、预取（按尝试次数封顶、与读者共用一次回源——等读者确实加入那次回源再放行，不靠睡眠）。
- 其余：`cache`、`config`（读不懂的值拒绝启动）、`settings`、`schedule`、`admin`（任务同一时刻只跑一次）、`trans`（语料文件逐条校验标记）、`vndb`（以真实 dump 值为样本）、`db/guard`、`db/similar`、`netproxy`。

**`TestAllAges`**：在测试库里按导入的真实流程建一代（真 DDL、全部派生、上线），起读 API，以访客、会员、全站开关三种身份走 HTTP：列表与总数、按 id 查询的 `withheld`、作品的发行与封面、`/meta/viewer`、遮罩与不遮罩的整库统计、查不了表时访客得到 503；保留作品的派生列、筛选、排序与 `/stats/vn` 只按看得见的发行；经被挡的标签与发行问不出来；截图、配音、角色出场与 `instance_of` 不指向被挡的东西；改一个发行的分级、重建列表，访客的列表与统计立刻跟上（用内存缓存，和上线一样）。最后是搜索：给线上一代补建描述表（`BuildSearchText`）后，`description=` 每个词都要出现、大小写与全半角折叠、BBCode 地址不算、访客搜不到被挡的作品；标签能用译名搜到；删掉视图后 `EnsureSearchLabels` 补回、搜索照常；没有描述表时 `description=` 回 503 而不是 500。

**用户服务（`backend/users`）**

- `auth`：账号规则、只读配置的那个 cookie 名、hash 往返。
- `api`：限流的滑动窗口、`X-Forwarded-For` 只信末项、条目 id 解析、`/auth/viewer`；`ceiling_test.go` 经 HTTP 测各项上限（登录与注册 429、单批数量、每页条数、整表条数）；`settings_test.go` 测保存搜索的条数上限与被拒的请求。
- `store`：账号与起始列表、会话过期、列表只属于主人、批量加 / 删 / 移保留收藏时间、评分、注销的级联、偏好与命名搜索。
- `backup`：何时该备份、只认自己写的文件名、写出的备份 `pg_restore` 读得了、清理旧备份失败时新备份照样算数。
- `schedule`、`config`。

**上限都有测试**（开发不设限、上线设限，测试保证生效）：读 API 的页大小、成本、筛选条数、字段深度、搜索词数、id 个数、关系图深度与节点数，每项都同时测"0 即不限"；用户服务的各项经 HTTP 测到 429 / 400。

**没有的**：导入路径对真实上游的端到端测试——上游索引的形态真变了，要跑一次才知道。

## 四、前端单元与组件测试

`frontend/tests/`，与 `src/` 完全分开（`src/` 不引用 tests，`next build` 也看不到）。单元测试文件叫 `*.test.ts(x)`，端到端叫 `*.spec.ts`。

- 默认 node 环境；组件测试在文件头写 `@vitest-environment jsdom`。
- jsdom 不排版：靠位置的（段落导航点亮哪段、横滚到没到头）由测试自己给元素设尺寸；`offsetParent` 恒为 null、数字框回车不提交表单，测试里各有说明。要量真实排版的（吸顶、对齐、溢出）放 e2e。
- jsdom 用脚本派发事件，复现不了"React 在事件冒泡途中跑完 effect"这类时序（例如触屏点开提示框随即被同一下关掉），这类回归放 e2e。
- 跑组件测试要用 `pnpm test -- <路径>`，直接跑 vitest 解析不了 `@/`。

## 五、端到端（Playwright）

```
frontend/tests/e2e/
├── playwright.config.mts             对着运行中的站（默认 http://127.0.0.1:17030，E2E_BASE_URL 可改），单 worker
├── playwright.deployed.config.mts    同一套用例，对着按上线配置另起的一套站
├── setup.ts / teardown.ts            起停临时服务（见下）；建的临时目录记在状态文件里，teardown 停掉进程后删除
├── fixtures.ts                       user / member / admin
├── transition.ts                     midway：把换页过渡停在旧页淡出的一半来量
└── *.spec.ts
```

**两种模式**

- **`pnpm test:e2e`**：对着 `start.ps1` 起的站，测的是那份**运行中的构建**，不是工作区的代码。设了 `NEOVNDB_USERS_TEST_DB_URL` 时起一个临时用户服务（:17035），页面对 `/userserve` 的请求转给它。要读 API 把测试账号当会员（不遮罩）的用例在这里**跳过**：线上的边缘拿 cookie 问的是真实用户服务，它不认识测试账号；服务端渲染的请求也拦不到，没法绕。
- **`pnpm test:e2e:deployed`**：在现有站旁另起一整套——读 API（:17037，用 `.env.sample` 里的上限，临时的设置目录，不更新不预取）、生产构建的 Next（:17038）、同一份 Caddyfile 起的边缘（:17036）、临时用户服务（:17035）。与现有站共用镜像库和图片，只读。全部用例都跑。上限会不会在页面上撞墙，在这里先看到。

**站在运行时不要直接 `pnpm build`**：运行中的 `next start` 读的是 `frontend/.next`，构建会把它整个换掉，线上页面引用的脚本随即 500。部署模式的 e2e 因此构建进 `.next-check`（`NEOVNDB_NEXT_DIR`，见 `next.config.ts`）并从那里起；手动构建也照样：`$env:NEOVNDB_NEXT_DIR = '.next-check'; pnpm build`。`E2E_SKIP_BUILD=1` 时 `.next-check` 里没有构建就报错。

**fixtures**

- `user`：经 API 在临时服务上注册新账号、塞 cookie、把页面的 `/userserve` 转过去；页面里从不输入密码；没有测试库就跳过。
- `member`：`user`，但只在部署模式下跑（理由见上）。
- `admin`：`user` 再用临时服务的 `users admin` 授予；非部署模式下页面对 `/vndbserve/admin`、`/imgserve/admin` 的请求直接转给 17031 / 17032（线上边缘会去问真实的用户服务）。

**Windows 上停的是整棵进程树**（`taskkill /T`）：边缘的 caddy 经 Chocolatey 的 shim 启动，只停 shim 时真正的 caddy 会留下来占着端口。

**各文件覆盖什么**

| 文件 | 内容 |
|---|---|
| `allages` | 线上一代有全年龄列表时：访客被遮罩、菜单说明原因；被挡条目对访客显示"不显示"与带回跳的登录按钮；不存在的地址仍是 Nothing here；会员能看到；访客的作品总数少于会员。没有列表时整个跳过 |
| `layout` | 二十几个主要页面（含登录后与管理页）在 320 / 390 / 768 / 1024 / 1440 宽下整页与各滚动栏不横向溢出；慢 4G 节流下 CLS < 0.02；正文里可点的元素不被 `position: fixed` 的东西压住（中心与四角五点）；选择模式下翻页链接不在操作条底下。`E2E_SHOTS=<目录>` 顺手存截图 |
| `navigation` | 无效 id 是 404 而不是 500、段落导航、Similar 横滚、`/q` 一条即跳、发行行对齐、分面计数、关系图步数与卡片全部挂载、点空白处放开选了一半的路径、触屏点开的提示框不被同一下关掉、换页过渡 |
| `lists` | 翻页跳转、超过最后一页给出链接、空的跳页不跳、方向键、按名字嵌套标签、用日文译名搜到标签（API 与列表页）、非法值报错 |
| `catalog` | 声优页列角色、制作方去掉空的与重复的标签页、剧透开关关住手动展开的 [spoiler]、特征页的计数按读者的剧透上限 |
| `content` | BBCode、图标、原文模式 |
| `images` | 列表用 cv / cv.t、详情页用 st / ch、cv.t 缺失时给原图；全部 200，或盘上还没有时 302 到 vndb |
| `api` | `/meta/openapi` 与 `/api` 页；作品的角色按定位轻重排 |
| `collect` | vndb 已删条目的占位卡与移除 |
| `admin` | 未登录 401、非管理员 403 与页面拒绝、管理员在一页上看到三组、描述丢标记被拒（被拒的写入若意外通过会写回原值）；部署模式下在页面上改设置再改回 |
| `shelf` | 按我的评分排序、换列表时列表栏不重建、`/u` 与具体列表互跳时旧页不缩放、按 vndb 字段排序时真的分页、跨页勾选、评分页批量设分与清除 |
| `account`、`sync` | 账号流程；偏好跟账号、命名保存搜索、未登录时只记本机最近搜索 |
| `dashboard` | 仪表盘数出所持作品并给出推荐；读 API 不返回的作品不让统计块一直"计算中" |
| `stats` | 顶栏入口、总数与排行链接、性别切换、各类总数等于各自列表的数 |

输出只落在 `tests/e2e/.results/`（不带配置跑会写到 `frontend/test-results/`，两处都在 `.gitignore` 里）。

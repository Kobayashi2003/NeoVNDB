## 一句话

把 vndb 官方的公开 dump **原样镜像**进本地 Postgres，在上面包一层只读 HTTP API 和一个浏览站；读者的账号、收藏、评分在另一个服务、另一个库里——全项目只有这部分不能从上游重建。

## 组成

```
                         浏览器
                           │
                   边缘（Caddy）:17030          唯一对外的地址
     /vndbserve     /imgserve     /userserve     其余
         │              │              │           │
   读 API :17031   图片镜像 :17032  用户服务 :17033  Next :17034
         │              │              │
     Postgres       data/images     Postgres
     （镜像）                       （账号）
```

| 部分 | 目录 | 做什么 |
|---|---|---|
| 读 API | `backend/vndb`（`neovndb serve`） | 七种类型（作品、发行、角色、制作方、人员、标签、特征）一个查询端点，外加关系图、分面计数、相似与推荐、整库统计；顺带按计划更新镜像 |
| 图片镜像 | `backend/vndb`（`neovndb images`） | vndb 图片的逐字节镜像；盘上有的由边缘直接发；按计划预取 |
| 导入 | `backend/vndb`（`neovndb import` / `update`） | 下载 dump、灌进新的一代、派生、熔断检查、原子换代 |
| 用户服务 | `backend/users` | 账号、会话、收藏夹、评分、偏好、保存的搜索、用户库备份 |
| 边缘 | `edge/Caddyfile` | 路由白名单、管理员与访客判定、静态图片 |
| 前端 | `frontend`（Next.js） | 浏览站与管理页 |

端口都在 NeoVNDB 的 17030–17039 段里（`project/PORTS.md`）；e2e 用 17035–17038。

## 数据怎么流

```
dl.vndb.org 的 dump ──下载、校验──► 归档 ──COPY──► vndb_next ──派生、熔断──► 换代 ──► vndb（线上）
                                                                               └──► vndb_prev（可回滚）
```

- **代次**：`vndb`（线上）、`vndb_prev`（上一代）、`vndb_next`（正在导入）。换代是一个事务里的三次 `ALTER SCHEMA RENAME`，线上永远不会半写。
- **派生**：dump 不导出、vndb 自己会算的东西（标签分数与继承、闭包、搜索索引、作品的发售日/语言/平台/开发商、全年龄列表、相似作品），导入时自己算。
- **熔断**：新一代上线前与线上一代比行数，缩水过多、少表、派生表为空就拒绝。
- **缓存**：响应按"代次 + 译文版本"做键，换代即整批作废，不用手动清。

取数时浏览器与 Next 的服务端都经边缘：没有"只在本机能用"的第二套地址。

## 谁能看到什么

- **鉴权全在边缘**：读 API 与图片镜像里没有一行鉴权代码。`/admin` 路由要用户服务确认是管理员才放行。
- **全年龄模式**：未登录的读者只看到全年龄内容（无 18+ 发行、无只有成人版的作品、无性相关标签与特征、无投票为性或暴力的图片）；管理员可以设为对所有人都如此。被挡的东西不发给浏览器，总数、搜索、统计都只算看得见的。定级在导入时做，见 `后端代码结构.md` 的全年龄一节。

## 长期约束

任何新功能都要过这几条：

- **本地库是一次 dump 的纯函数**：重新导入即完全重建，没有迁移、没有增量更新。自己的数据（译文、账号、收藏）必须待在生成 schema 之外。
- **不改任何来自 vndb 的数据**，不导入用户资料、评论、单条投票（只留聚合值）。
- **不依赖 Kana API**：运行时与导入时都不调。
- **镜像只存原件**：库是 dump 的逐字镜像，图片逐字节，不做缩放；缩略图用 vndb 自己发布的。
- **鉴权在边缘**：新服务只听回环（`127.0.0.1`），不写鉴权代码。
- **出站代理**：对外请求（下载 dump、回源取图）按 `HTTPS_PROXY` / `HTTP_PROXY`、再按 Windows 系统代理（Clash 开关的那个）选代理，都没有就直连；本机与私有地址、`NO_PROXY` 里的主机一律直连（`internal/netproxy`，规则来自 `D:\Program\Code\AGENTS.md`）。
- **上限开发不设、上线设、测试保证生效**：页大小、字段深度、搜索词数、登录次数这类，开发的 `.env` 一律为 0（不限），`.env.sample` 写上线用的值，每一项都有测试证明它真的生效。
- **先量再改**：怀疑有问题先证明它存在。
- **HTTP 200 不等于页面能用**：前端改动要在浏览器里确认水合。

## 技术栈

- 后端：Go（两个独立模块，不共享代码），pgx，sqlc 生成静态查询，查询层自己拼动态筛选。
- 数据库：PostgreSQL（镜像库 `neovndb`，账号库 `neovndb_users`）。
- 前端：Next.js App Router、React、Tailwind、TypeScript；关系图用 React Flow + ELK。
- 边缘：Caddy 2。
- 工具：pnpm、Vitest、Playwright、`go test`。
